## 2. 系统化分解思维链（Chain of Thought）

AI在分解时，必须严格执行以下**四个维度**的遍历检查，防止遗漏：

### 维度A：状态空间遍历（Finite State Machine）
- **问**：模块有多少个状态？状态跳转是否全部覆盖？非法状态跳转会发生什么？
- **产出**：状态覆盖、状态跳转覆盖、非法状态恢复测试点。

### 维度B：数据路径遍历（Data Path）
- **问**：数据从哪里来（Source）？经过哪些变换（Arithmetic/Logic）？存到哪里（Sink）？
- **产出**：数据完整性（CRC/ECC）、数据变换正确性、边界对齐（Unaligned）、端序（Endianness）测试点。

### 维度C：控制路径遍历（Control Path）
- **问**：配置寄存器何时生效（立即/下次传输）？中断/握手信号如何拉高拉低？
- **产出**：寄存器读写、配置动态切换（Dynamic Reconfiguration）、中断嵌套测试点。

### 维度D：反压/流控遍历（Flow Control）
- **问**：当上下游速度不匹配时，如何握手（Ready/Valid, AXI握手）？
- **产出**：吞吐率抖动、反压最坏情况（Back-to-Back after Backpressure）、死锁恢复测试点。

## 3. 通用模块类型特定检查列表（即插即用库）

当AI识别到特定类型的模块时，必须自动追加以下专项检查点：

### 3.1 总线/互联模块（如 AXI/AHB/APB Bridge, NoC）
| 专项维度 | 必须包含的测试点 |
| :--- | :--- |
| **地址解码** | 地址别名（Alias）、地址越界（Out-of-Range）、非对齐访问（Unaligned）响应。 |
| **ID管理** |  Outstanding传输乱序返回（Out-of-Order）、ID重映射冲突。 |
| **原子操作** |  Locked/Swap/CAS 操作在竞争条件下的正确性。 |
| **QoS/仲裁** | 高优先级饿死低优先级、权重比例准确性。 |

### 3.2 存储/缓存模块（如 SRAM Controller, Cache, FIFO）
| 专项维度 | 必须包含的测试点 |
| :--- | :--- |
| **ECC/奇偶校验** | 单比特纠错（SB）、双比特报错（DB）、纠错期间被写入的并发行为。 |
| **刷新与回写** |  Cache Line 脏数据回写（Write-back）过程中收到新的读请求。 |
| **替换算法** |  LRU/Random 替换策略的硬件实现正确性（无死锁）。 |
| **休眠/低功耗** | Retention 模式下数据保持，唤醒后快速响应。 |

### 3.3 计算/处理模块（如 ALU, DSP, Crypto Engine）
| 专项维度 | 必须包含的测试点 |
| :--- | :--- |
| **饱和/舍入** | 溢出（Overflow）、下溢（Underflow）、饱和截断边界值（Max+1）。 |
| **标志位** |  Zero/Carry/Negative/Overflow 标志位在流水线背靠背指令下的正确性。 |
| **旁路/转发** | 数据冒险（Data Hazard）的硬件旁路（Forwarding）是否生效。 |

### 3.4 时钟/复位/电源管理模块（Clock Gating, Power Switch）
| 专项维度 | 必须包含的测试点 |
| :--- | :--- |
| **异步复位同步释放** | 复位释放时跨时钟域（CDC）的亚稳态防护。 |
| **时钟切换** | 时钟动态切换时无毛刺（Glitch-free），切换期间总线被挂起。 |
| **上电顺序** | 多电源域上电/下电时序违反Spec时的保护机制。 |

## 4. 异常场景注入方法论（AI必须掌握的故障模型）

在分解“异常类”测试点时，请从以下维度强制注入故障：

| 故障模型 | 具体注入方式 | 适用模块示例 |
| :--- | :--- | :--- |
| **输入异常** | 输入数据有效信号（Valid）长时间拉低/随机断流。 | 所有从设备 |
| **输出阻塞** | 输出就绪信号（Ready）长时间拉低，制造极强反压。 | DMA, Bus Master |
| **资源耗尽** | 描述符队列已满、内部Buffer水位超限后继续发起请求。 | Ethernet MAC, PCIe |
| **超时** | 下游响应超时（Timeout），验证超时重传/中断上报。 | AXI Slave, I2C Master |
| **配置突变** | 在传输进行中动态改写控制寄存器。 | 中断控制器, 速率配置 |
| **并发冲突** | 同一时刻触发复位、中断、DMA传输和寄存器访问。 | 全局系统级 |

## 5. “好”测试点的评判标准（AI自查清单）

在输出最终清单前，AI必须对每个测试点进行自检，确保满足以下 **SMART-ICE** 原则：

1.  **S (Specific)** ：描述明确，不模糊。（❌ “测试读写功能” ➡️ ✅ “测试地址0x00写入0xA5后，读出是否仍为0xA5”）
2.  **M (Measurable)** ：有量化阈值。（必须有具体的时钟周期数、带宽MBps值）。
3.  **A (Achievable)** ：在标准UVM/仿真环境下可构造。
4.  **R (Relevant)** ：紧密关联模块Spec，不跑题。
5.  **T (Traceable)** ：能反向追溯到需求条目号。
6.  **I (Independent)** ：尽量减少前置依赖，可独立运行。
7.  **C (Corner-focused)** ：强制覆盖边界值（全0、全1、翻转点）。
8.  **E (Exhaustive)** ：关键组合（Cross-Corner）必须穷举。

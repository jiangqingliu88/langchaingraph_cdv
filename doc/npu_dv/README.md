## 文档性质

- **计划 / 覆盖计划**：可直接执行的计划（范围、验证项、覆盖目标、里程碑）。
- **报告 / 签核文档**：**结果模板**；`[填写]` 由执行人按实际回归、覆盖率、缺陷与证据补齐。
- 规范性依据：[NPU验证层级拆分与覆盖追踪规范_V2.3.md](NPU验证层级拆分与覆盖追踪规范_V2.3.md)

## 层级职责

| 层级 | 对象 | 核心目标 |
|---|---|---|
| L1 | glsu / llsu / mpu / vpu / niu / cmdsched / inst_disp / noc / npu_core | 功能穷举、协议、代码覆盖 |
| L2 | 多 Core Cluster（glsu + NoC + 共享 SRAM + 跨核同步） | 并发、仲裁、拥塞、死锁、一致性 |
| L3 | 完整 NPU | 真实模型端到端、性能、DVFS、长稳、安全 |

## 使用顺序

1. 先冻结 L1 计划与覆盖计划 → 执行 L1 回归 → 出 L1 报告 → L1 签核。
2. L1 证据可复用后，执行 L2 计划 → 覆盖 → 报告 → 签核。
3. L2 闭合后，执行 L3 模型/性能/长稳 → 报告 → 顶层签核。
4. 每层签核都必须有：覆盖报告、代码覆盖、缺陷/豁免、证据包、TB/RTL 封存。

## 1. 覆盖原则

1. L2 只覆盖**跨 IP / 跨 Core 交互**，不重复 L1 内部穷举。
2. 并发、仲裁、拥塞、一致性、死锁是 L2 的五个核心覆盖域。
3. 所有交互覆盖必须能追溯到 L1 IP 的覆盖证据。
4. 非法状态（越界 Core、非法路由、死锁）零容忍。
5. 性能类覆盖记录曲线与拐点，不只看平均值。

## 2. 并发覆盖

| 覆盖项 | 内容 | 目标 |
|---|---|---|
| Core 并发度 | 1 / 2 / 4 / 全 Core | 全档位 |
| 计算并发 | 多 Core 同时执行不同指令类型 | 组合覆盖 |
| 搬运并发 | 多 Core 同时触发 glsu | 并发场景覆盖 |
| 计算 + 搬运重叠 | 双缓冲流水 | 场景覆盖 |
| 中断穿插 | 并发中插入中断/异常 | 场景覆盖 |

## 3. 搬运仲裁覆盖（glsu + NoC）

| 覆盖项 | 内容 | 目标 |
|---|---|---|
| 仲裁场景 | 多请求同时到达、不同优先级 | ≥90% |
| 防饿死 | 低优先级长期可获服务 | 100% |
| 请求类型 | 读/写/预取/回写 | 100% |
| 依赖链 | 搬运与计算的先后关系 | ≥90% |
| 错误仲裁 | 非法请求被拒绝且不阻塞其他请求 | 100% |

---

## 9. 覆盖闭合规则

```text
required    = 场景/仓总数 − ignore
waived      = 已批准豁免
denominator = required − waived
coverage    = hit / denominator
```

- 非法状态命中即失败；
- 性能覆盖只记录事实，不用平均值掩盖拐点；
- 所有豁免必须有 owner / approver / reason / expires。

## 10. 覆盖证据

| 类型 | 证据 |
|---|---|
| 交互覆盖 | 覆盖率报告（bin 级） |

| 性能 | 带宽/延迟曲线 + 配置 |
| 代码覆盖 | vcover（子系统 RTL） |

---

## 11. 签核条件

1. 并发、仲裁、NoC、一致性、同步五域关键仓达标。
2. 非法状态 0 命中。
3. 无未解释死锁；长稳通过。
4. 性能达到设计目标，拐点已评审。
5. L1 证据可追溯、可复用。

## 1. 覆盖原则

1. **业务优先**：L3 覆盖以真实模型/真实指令流为核心，不追求 IP 内部穷举。
2. **加权覆盖**：按模型耗时/重要性加权，不用简单平均。
3. **证据咬合**：L3 每个覆盖项必须有 L1/L2 证据或顶层直接证据。
4. **失败可下沉**：L3 失败必须能在 L2/L1 复现或定位。
5. **性能与功能分开**：功能通过不等于性能达标。

| 指标 | 内容 | 目标 |
|---|---|---|
| 吞吐 | 推理/秒、TOPS | 设计目标 |
| 延迟 | 端到端、单层 | 设计目标 |

| 重叠效率 | 计算/搬运重叠 | 设计目标 |

性能数据必须带模型、batch、频率、配置、版本；不同配置不直接比较。

---

## 6. 覆盖闭合规则

```text
required    = 计划项 − ignore
waived      = 已批准豁免
denominator = required − waived
coverage    = hit / denominator
```

- 模型加权覆盖按耗时权重计算；
- 非法/失败场景单独统计，不进分母美化；
- 性能只记录事实，不用平均值掩盖长尾。

---

## 7. 覆盖证据

| 类型 | 证据 |
|---|---|
| 模型覆盖 | 模型清单 + 加权覆盖报告 |
| 指令流 | 编译器输出 + 覆盖报告 |
| 三方差分 | 比对报告 |
| 性能 | 曲线 + 配置 + 版本 |
| 长稳 | 日志 + 监控 |
| 安全/复位/错误 | 专项报告 + 波形 |

---

## 8. 签核条件

1. 模型加权覆盖 100%，目标模型全部通过。
2. 指令流覆盖目标模型，边界指令覆盖。
3. 三方差分在阈值内。
4. 性能达到设计目标或已评审。
5. DVFS / 长稳 / 复位 / 安全专项通过。
6. L1/L2 证据可追溯，无未解释缺口。

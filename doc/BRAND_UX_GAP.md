# SignOffAI 前端品牌对齐分析

> 对照 BRAND.md 三大核心价值：可追溯 · 可审计 · 可治理

---

## 一、现状诊断

| 价值 | BRAND.md 承诺 | 后端实现 | 前端体现 | 差距 |
|---|---|---|---|---|
| **可追溯** | 任意 Agent 动作可复现、每步有 hash | manifest.json / evidence_hash / vagent dump | 模块卡片底部一行小字 hash | 🔴 大 |
| **可审计** | artifact manifest + 审计日志 + 完整性校验 | 版本管理 API / 审计日志表 / manifest hash | 版本页只有表格，无 diff，无校验 | 🔴 大 |
| **可治理** | 项目隔离、RBAC、Token 预算、人工审批 | RBAC 角色 / 模块分配 API / Token 统计 | 角色切换按钮 + 待验证徽标 | 🟡 中 |

**结论**：后端能力完整，前端只展示了 20% 的价值。

## 二、可追溯 — 前端改造方案

在签核证据链页面，用时间线替代表格：

```
┌─────────────────────────────────────────────────────────┐
│ 🔗 证据链追溯 — run_20260808_155639                     │

│  📄 spec ──→ 🏗 design ──→ 📐 UVM ──→ 🧪 test ──→ ✅ signoff  │

│  ✅ PASS    ⚠ DEGRAD  ✅ PASS    ⏭ SKIP    🔒 LOCKED   │

│  点击任意阶段 → 展开输入/输出/工具调用/hash              │
```

每个模块卡片上不是一小行 hash，而是可点击的"追溯"按钮：

在流水线完成后的控制台，以及签核页面，增加：

## 五、落地优先级

| 优先级 | 项目 | 理由 |
|---|---|---|
| **P0** | 证据链时间线可视化 | "可追溯"最直观的体现 |
| **P0** | 完整性校验面板 | "可审计"的核心功能 |
| **P1** | 模块卡片追溯入口 | 减少点击层级 |
| **P1** | Token 预算仪表盘 | BRAND.md 承诺项 |
| **P1** | 审批工作流可视化 | "可治理"的核心功能 |
| **P2** | 版本 Diff 对比 | 增强审计能力 |
| **P2** | RBAC 权限矩阵 | 增强治理透明度 |
| **P2** | 审计日志增强 | 筛选+搜索 |

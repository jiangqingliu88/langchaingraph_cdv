## 1. 架构核心基石：TWU 的引入

### 1.1 设计哲学

在 TPB（Tensor Processing Block，张量处理块）中，**功能单元（FC：TCU、CVU、DTDU、GSDU）本身不具备地址生成能力**。
它们的数据读写完全依赖内部 **TWU（Tensor Walking Unit，张量遍历单元）** 生成复杂的非线性、嵌套循环地址序列。

> **一句话**：TWU 把"地址计算"从软件/指令流中剥离，变成纯硬件状态机的走步逻辑。
> 程序员不再写 `load 0x1000, load 0x1004, ...`，而是配置一个 3 层嵌套循环，
> TWU 自动吐出几万个（甚至非连续、滑窗、转置、切片）物理地址。

### 1.2 TWU 的职责与配备

- **配备规则**：每个功能单元通常包含 **2 个或更多输入 TWU**（读取输入激活 / 权重），
  以及 **1 个输出 TWU**（写回计算结果）。
- **地址生成逻辑**：TWU 内部是**多层嵌套循环状态机**，通过配置 `Initial`、`Step`、`Final`
  控制访问路径；最终物理地址 = 各层当前计数之和（含基址偏移）。
- **双缓冲支持**：TWU 通过 `Buffer_Offset` 在不同物理内存区域间无缝交替切换，
  支持极致流水线并行，**无需专用数据通路**（复用地址总线的空闲周期）。

```
                    ┌─────────────────────────────────────────┐
                    │                TPB                       │
                    │  ┌─────────────┐  ┌──────────────────┐  │
   DRBN / HBSM ◄───►│  │  TWU-Input0 │  │                  │  │
   (数据流)         │  │  TWU-Input1 │──►│  功能单元(FC)     │  │
                    │  │  TWU-InputN │  │  TCU/CVU/DTDU/   │  │
                    │  └─────────────┘  │  GSDU             │  │
                    │                   │                  │  │
                    │  ┌─────────────┐  └──────────────────┘  │
                    │  │  TWU-Output │◄── 计算结果写回        │
                    │  └─────────────┘                        │
                    └─────────────────────────────────────────┘
```

## 2. 微码包（Microcode Packet）物理结构

TPB 在执行一个算子之前，**CIQ（Command Issue Queue，指令分发队列）** 分发给它的
是一个微码包（几百到几千 Byte）。v5.0 中，`TWU_CONFIG_BLOCK` 占据包的**核心位置**。

### 2.1 微码包物理流格式（CIQ → TPB 引擎）

| 流分段 | 字段名 | 大小 | 物理解析动作 |
|--------|--------|------|--------------|
| 流前部 | `OPCODE` | 4 Byte | 底层驱动类型（0=DTDU, 1=CVU, 2=TCU, 3=GSDU, 4=CSU） |
| 流前部 | `PACKET_LEN` | 4 Byte | 微码负载的总长度（含头部） |
| 流前部 | `TTU_SYNC_HEADER` | 32 Byte | 本地同步与迭代控制头，由 SU（同步单元）截获解析 |
| 流中部 | `TWU_CONFIG_BLOCK` | 变长（核心） | 张量遍历配置，定义本功能单元内所有 TWU 的嵌套循环参数 |
| 流后部 | `FUNCTION_CFG` | 变长 | 具体算子配置（卷积核尺寸、矩阵维度、精度选择等） |

```
┌──────────┬──────────┬──────────────────┬───────────────────┬───────────────────┐
│  OPCODE  │PKT_LEN   │  TTU_SYNC_HEADER │  TWU_CONFIG_BLOCK │  FUNCTION_CFG     │
│  4 B     │  4 B     │  32 B            │  变长 (TLV 流)     │  变长              │
└──────────┴──────────┴──────────────────┴───────────────────┴───────────────────┘
     流前部                    流前部              流中部                流后部
```

### 2.2 TTU_SYNC_HEADER（32 Byte 字段布局）

| 偏移 | 字段 | 位宽 | 语义 |
|------|------|------|------|
| 0 | `sv_depend_id` | 8 bit | 等待的信号量 ID（0 = 无需等待）；SU 挂起流水线直到 SV 置位 |
| 8 | `sv_release_id` | 8 bit | 执行完成后释放的信号量 ID（0 = 不释放） |
| 16 | `loop_max` | 16 bit | 包级迭代次数（0 = 无包级循环，由 TWU 驱动） |
| 32 | `loop_stride` | 16 bit | 包级迭代的地址步长 |
| 48 | `loop_exit_act` | 4 bit | 执行完成后的动作（0=无, 1=CSU 中断, 2=释放 SV, 3=两者） |
| 52 | `flags` | 12 bit | 保留 / 调试位 |
| 64 | `reserved` | 192 bit | 保留（对齐 256 bit） |

### 2.3 TWU_CONFIG_BLOCK 的 TLV 流格式

`TWU_CONFIG_BLOCK` 在物理总线中以 **TLV（Type-Length-Value）** 流形式存在：

```
┌──────────┬──────────┬──────────────────────────────┐
│ TYPE (1B)│ LEN (2B) │ VALUE (变长)                  │
└──────────┴──────────┴──────────────────────────────┘
```

| TYPE | 含义 |
|------|------|
| `0x01` | TWU_LEVEL_CONFIG（单层循环配置） |
| `0x02` | TWU_BLOCK_START（某 TWU 的配置块起始标记） |
| `0x03` | TWU_BLOCK_END |
| `0x04` | BUFFER_OFFSET（最外层双缓冲偏移） |
| `0x0F` | END_OF_BLOCK（TWU_CONFIG_BLOCK 结束） |

## 3. TWU_CONFIG 结构与硬件状态机

### 3.1 TWU_LEVEL_CONFIG 结构体（单层循环）

```
[ Input_TWU_0_Level_N ]
  Init:     <起始地址偏移>          # 计数器初始值
  Step:     <每次递增步长>
  Final:    <达到此值触发上层递增>    # 自身重置为 Init
  [可选] Buffer_Offset: <双缓冲偏移> # 仅最外层支持
```

### 3.2 完整示例（3 层嵌套 + 双缓冲）

```
[ 输入 TWU 0 配置块 ]                     # 读取输入特征图
  Input_TWU_Level_0 (最内层循环):
    Init: 0
    Step: 1
    Final: 16
  Input_TWU_Level_1 (第二层循环):
    Init: 0
    Step: 16
    Final: 64
  Input_TWU_Level_2 (最外层循环，含双缓冲支持):
    Init: 0
    Step: 256
    Final: 1024
    Buffer_Offset: 1024                   # 当该层递增时，基地址整体偏移 1024

[ 输入 TWU 1 配置块 ]                     # 例如矩阵乘法：读取权重矩阵
  ...（嵌套循环配置）

[ 输出 TWU 配置块 ]                       # 写回结果
  ...（嵌套循环配置）
```

### 3.3 TWU 硬件执行逻辑（形式化）

TWU 状态机在驱动功能单元时遵循**纯硬件走步规则**：

```
输入:  levels[0..L-1] = {Init, Step, Final}   (levels[0] = 最内层)
       base_addr, buf_offset, buf_sel

初始化:
  for l in 0..L-1:  cnt[l] = levels[l].Init
  buf_sel = 0

每周期迭代 (功能单元请求一个地址):
  addr = base_addr + buf_sel * buf_offset
  for l in 0..L-1:  addr += cnt[l]
  输出 addr

  触顶判定 (从最内层向外):
  cnt[0] += levels[0].Step
  for l in 0..L-1:
    if cnt[l] >= levels[l].Final:
      cnt[l] = levels[l].Init          # 重置/回滚
      if l+1 < L:
        cnt[l+1] += levels[l+1].Step   # 外层递增
      else:
        完成 (所有层触顶)               # SU 检测 Final 条件 → 触发 loop_exit_act

  双缓冲切换 (可选):
  if 最外层触顶 and buf_offset > 0:
    buf_sel ^= 1                       # 无缝切换到另一缓冲区
```

**关键规则要点**（对应你的规范）：
1. **最内层规则**：最内层循环的 Value 计数器每次迭代无条件递增（递增量为 Step）。
2. **触顶触发更新**：每当某层循环的 Value 达到其 `Final` 值，外层循环的 Value 计数器按该外层的 Step 递增。
3. **重置与回滚**：触顶的层在下次递增前，自动从 `Initial` 重新开始。
4. **最终地址生成**：TWU 输出物理地址 = 所有循环层级当前 Value 计数之和（+ 基址 + 缓冲偏移）。

### 3.4 状态迁移图

```
                ┌──────────┐
                │  IDLE    │◄──────────────┐
                └────┬─────┘               │
          收到配置包 │                      │
                ┌────▼─────┐               │
                │ CONFIG   │               │
                └────┬─────┘               │
          等待 SV 置位│                     │
                ┌────▼─────┐               │
                │ WALKING  │──最内层递增──►│
                │ (走步)    │               │
                └────┬─────┘               │
      所有层触顶      │                     │
                ┌────▼─────┐               │
                │ DONE     │──loop_exit_act│
                └──────────┘               │
                   │ 双缓冲: buf_sel ^= 1  │
                   └──────────────────────┘
```

## 4. 双缓冲（Double Buffering）硬件切换

### 4.1 机制

- TWU 支持在最外层循环指定 `Buffer_Offset`。
- **物理意义**：当外部控制器向 HBSM（High-Bandwidth Shared Memory）输入当前数据块时，
  TWU 可无缝切换到另一缓冲区（基地址 + `Buffer_Offset`）。

### 4.2 流水线优势

```
时间线:
  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
  │ TCU 计算 缓冲区A │  │ TCU 计算 缓冲区B │  │ TCU 计算 缓冲区A │
  └──────────────┘  └──────────────┘  └──────────────┘
            └─ DTDU 搬入 缓冲区B ─┘  └─ DTDU 搬入 缓冲区A ─┘
```

- 一个缓冲区正被 TCU 计算时，另一缓冲区的数据已被 DTDU 从外部搬入。
- **无需软件干预**，彻底消除数据搬运带来的流水线停顿。

### 4.3 寄存器级握手

| 信号 | 方向 | 语义 |
|------|------|------|
| `twu_buf_sel` | TWU → FC | 当前活动缓冲区选择（0=A, 1=B） |
| `twu_buf_switch_req` | FC → TWU | 计算推进到缓冲区边界，请求切换 |
| `twu_buf_switch_ack` | TWU → FC | 切换完成 |
| `hbsm_buf_full[1:0]` | DTDU → TWU | 对应缓冲区数据已就绪（触发 SV 或直接放行） |

## 5. TPB 指令集总览（5 大配置类）

> **M100 的统一性**：一条完整配置指令 = **TTU 同步头 + TWU 遍历配置 + 功能引擎具体参数**。
> 即：对 **功能单元（FC）、同步单元（SU）、张量遍历单元（TWU）** 的三合一批量配置。

| OPCODE | 引擎 | 名称 | 是否携带 TWU_CONFIG_BLOCK | 典型操作 |
|--------|------|------|--------------------------|----------|
| `0` | DTDU | 数据搬运与变换 | ✅（输入 TWU + 输出 TWU） | LOAD / STORE / TRANSFORM |
| `1` | CVU | 向量并行计算 | ✅（2×输入 TWU + 输出 TWU） | VADD / VMUL / VRELU |
| `2` | TCU | 张量/矩阵计算 | ✅（输入 TWU A/B + 输出 TWU） | MATMUL / CONV |
| `3` | GSDU | 散射/聚集与自定义 | ✅（输出 TWU 任意写） | GATHER / SCATTER / XMIT |
| `4` | CSU | CPU 启动与中断 | ❌（无数据访问） | LAUNCH / INT |

## 6. DTDU 类：数据搬运与变换（OPCODE = 0）

### 6.1 概述

- **物理动作**：驱动 DTDU（Data Transform DMA Unit）执行数据变换 DMA。
- **TWU 场景**：
  - 输入 TWU：从外部 **DRBN**（DRAM Block Network / 片外存储）读取连续/非连续数据块；
  - 输出 TWU：将格式化后的数据写入 **HBSM**。
- **典型配置**：`DTDU.LOAD`，由 TWU_CONFIG_BLOCK 定义数据如何"刮取"并写入。

### 6.2 FUNCTION_CFG 字段

| 字段 | 位宽 | 语义 |
|------|------|------|
| `dtdu_op` | 4 bit | 0=LOAD, 1=STORE, 2=TRANSFORM |
| `src_base` | 32 bit | 源基址（DRBN） |
| `dst_base` | 32 bit | 目标基址（HBSM） |
| `elem_width` | 4 bit | 0=8b, 1=16b, 2=32b, 3=bf16, 4=fp32 |
| `transform` | 8 bit | 0=直通, 1=转置, 2=切片, 3=填充, 4=dequant |

### 6.3 指令字（物理布局）

```
OPCODE(4B) | PKT_LEN(4B) | TTU_SYNC_HEADER(32B)
          | TWU_CONFIG_BLOCK (in_twu: 刮取路径; out_twu: 写入路径)
          | dtdu_op(4b) | src_base(32b) | dst_base(32b) | elem_width(4b) | transform(8b)
```

### 6.4 示例：非连续行刮取（stride 加载）

```
DTDU.LOAD
  TTU_SYNC_HEADER: sv_depend_id=3 (等 DMA 信号), loop_exit_act=2 (释放 SV)
  Input_TWU (刮取 DRBN 中非连续行):
    L0: Init=0  Step=1  Final=128    # 行内连续 128 元素
    L1: Init=0  Step=4096 Final=32   # 每行间隔 4096 元素 (stride)
  Output_TWU (紧凑写入 HBSM):
    L0: Init=0  Step=1  Final=128
    L1: Init=0  Step=128 Final=32    # 连续排布
```

## 7. CVU 类：向量并行计算（OPCODE = 1）

### 7.1 概述

- **物理动作**：驱动 CVU（Compute Vector Unit）进行大规模 SIMD 运算。
- **TWU 场景**：输入 TWU 从 HBSM 抓取两个连续向量片段；输出 TWU 写回结果。
- **典型配置**：`CVU.VADD`，由 TWU 的 `Step` 参数控制向量长度的递增步进。

### 7.2 FUNCTION_CFG 字段

| 字段 | 位宽 | 语义 |
|------|------|------|
| `cvu_op` | 4 bit | 0=VADD, 1=VMUL, 2=VRELU, 3=VMIN/MAX, 4=VEXP |
| `vec_len` | 16 bit | 向量长度（与 TWU 内层 Final 一致） |
| `lane_width` | 4 bit | 每 lane 位宽（SIMD lane 配置） |
| `acc_mode` | 2 bit | 累加模式（0=独立, 1=累加, 2=饱和） |

### 7.3 指令字

```
OPCODE=1 | PKT_LEN | TTU_SYNC_HEADER
        | TWU_CONFIG_BLOCK (in0: vecA; in1: vecB; out: vecC)
        | cvu_op(4b) | vec_len(16b) | lane_width(4b) | acc_mode(2b)
```

### 7.4 示例：VADD

```
CVU.VADD
  Input_TWU_0: L0 Init=0 Step=1 Final=512    # 读 vecA[0:512]
  Input_TWU_1: L0 Init=4096 Step=1 Final=512 # 读 vecB (基址+4096)
  Output_TWU:  L0 Init=8192 Step=1 Final=512 # 写 vecC
```

## 8. TCU 类：张量/矩阵计算（OPCODE = 2）

### 8.1 概述

- **物理动作**：驱动 TCU（Tensor Compute Unit）执行高吞吐矩阵乘法（GEMM）与卷积（CONV）。
- **TWU 场景**（TWU 发挥最大优势之处）：
  - 输入 TWU A：读取输入特征图矩阵；
  - 输入 TWU B：读取权重矩阵；
  - 输出 TWU C：写回结果矩阵。
  - **卷积的滑动窗口等复杂非线性地址，完全由 Step/Final 嵌套循环自动生成。**

### 8.2 FUNCTION_CFG 字段

| 字段 | 位宽 | 语义 |
|------|------|------|
| `tcu_op` | 4 bit | 0=MATMUL, 1=CONV2D, 2=CONV3D, 3=POOL |
| `M` | 16 bit | 行维（输出行数） |
| `K` | 16 bit | 收缩维（GEMM 内积长度 / 卷积通道内积） |
| `N` | 16 bit | 列维（输出列数） |
| `kernel_h/kernel_w` | 8+8 bit | 卷积核尺寸 |
| `stride_h/stride_w` | 4+4 bit | 卷积步长 |
| `pad_h/pad_w` | 4+4 bit | 填充 |
| `dtype` | 4 bit | 0=int8, 1=int16, 2=bf16, 3=fp16, 4=fp32 |

### 8.3 指令字

```
OPCODE=2 | PKT_LEN | TTU_SYNC_HEADER
        | TWU_CONFIG_BLOCK (inA: 特征图; inB: 权重; outC: 结果)
        | tcu_op(4b) | M(16b) | K(16b) | N(16b)
        | kernel_h(8b) | kernel_w(8b) | stride_h(4b) | stride_w(4b)
        | pad_h(4b) | pad_w(4b) | dtype(4b)
```

### 8.4 GEMM 的 TWU 配置（M×K·K×N → M×N）

```
TCU.MATMUL  M=64, K=64, N=64
  Input_TWU_A (特征图, M×K):
    L0: Init=0     Step=1  Final=64    # K 维连续
    L1: Init=0     Step=64 Final=64    # M 维
  Input_TWU_B (权重, K×N):
    L0: Init=0     Step=1  Final=64    # N 维连续
    L1: Init=0     Step=64 Final=64    # K 维
  Output_TWU_C (结果, M×N):
    L0: Init=0     Step=1  Final=64    # N 维
    L1: Init=0     Step=64 Final=64    # M 维
    (最外层可加 Buffer_Offset 双缓冲)
```

### 8.5 CONV2D 的 TWU 配置（滑动窗口的魔法）

> 卷积的**非线性访存**（滑窗、多通道、padding）由嵌套循环自然表达：

```
TCU.CONV2D  M=H*W, K=C*kh*kw, N=Co, kernel=3x3, stride=1, pad=1
  Input_TWU_A (输入特征图 H×W×Cin, 滑窗展开):
    L0: Init=0        Step=1   Final=3      # 核宽 kw (窗口内)
    L1: Init=0        Step=W   Final=3      # 核高 kh (窗口跨行)
    L2: Init=0        Step=1   Final=Cin    # 通道
    L3: Init=0        Step=W*Cin Final=H*W  # 空间位置 (滑窗)
  Input_TWU_B (权重 Co×Cin×3×3):
    L0: Init=0        Step=1   Final=3      # kw
    L1: Init=0        Step=3   Final=3      # kh
    L2: Init=0        Step=9   Final=Cin    # Cin
    L3: Init=0        Step=Cin*9 Final=Co   # Co
  Output_TWU_C (输出 H'×W'×Co):
    L0: Init=0        Step=1   Final=Co
    L1: Init=0        Step=Co  Final=H'*W'
    Buffer_Offset: (H'*W'*Co)               # 双缓冲输出
```

---

## 9. GSDU 类：散射/聚集与自定义计算（OPCODE = 3）

### 9.1 概述

- **物理动作**：驱动 GSDU（Gather/Scatter Data Unit）进行数据重组、Gather/Scatter 与特定加速（如加密/校验）。
- **TWU 场景**：输出 TWU 负责将数据按**非连续映射**写入 HBSM 任意位置。
- **典型配置**：`GSDU.XMIT` 或 `GSDU.CUSTOM`。

### 9.2 FUNCTION_CFG 字段

| 字段 | 位宽 | 语义 |
|------|------|------|
| `gsdu_op` | 4 bit | 0=GATHER, 1=SCATTER, 2=XMIT, 3=CUSTOM |
| `map_mode` | 4 bit | 0=线性, 1=索引表, 2=位反转, 3=自定义表 |
| `idx_base` | 32 bit | 索引表基址（map_mode=1/2 时使用） |
| `custom_func_id` | 8 bit | 自定义加速函数 ID（crypto/checksum 等） |

### 9.3 指令字

```
OPCODE=3 | PKT_LEN | TTU_SYNC_HEADER
        | TWU_CONFIG_BLOCK (输出 TWU 定义任意写映射)
        | gsdu_op(4b) | map_mode(4b) | idx_base(32b) | custom_func_id(8b)
```

---

## 10. CSU 类：CPU 启动与中断（OPCODE = 4）

### 10.1 概述

- **物理动作**：操作 CSU（CPU Start-up Unit）。
- **注意**：CSU **不直接涉及数据访问**，因此该引擎的指令**不带 TWU_CONFIG_BLOCK**。
- **职责**：接收 RISC-V 扩展指令，并在循环结束后通过**紫线（中断线）**向外部发送硬件中断。

### 10.2 FUNCTION_CFG 字段

| 字段 | 位宽 | 语义 |
|------|------|------|
| `csu_op` | 4 bit | 0=LAUNCH, 1=WAIT, 2=INT, 3=SYNC |
| `cpu_id` | 8 bit | 目标 RISC-V 核 ID |
| `int_vec` | 16 bit | 中断向量号 |
| `sv_signal` | 8 bit | 关联信号量 |

### 10.3 指令字（无 TWU_CONFIG_BLOCK）

```
OPCODE=4 | PKT_LEN | TTU_SYNC_HEADER (loop_exit_act 常=1)
        | csu_op(4b) | cpu_id(8b) | int_vec(16b) | sv_signal(8b)
```

## 11. 完整业务闭环：双缓冲流水线卷积算子

### 11.1 CIQ 下发微码包

```
[ 流前部 ]
OPCODE = 2 (TCU)                     # 驱动引擎是 TCU
PACKET_LEN = <总长度>

[ 流前部 ]
TTU_SYNC_HEADER
  sv_depend_id: 5                    # 等待外部 DMA 搬完数据(信号量 SV_5)
  sv_release_id: 6                   # 完成后释放 SV_6 给下游
  loop_max: 0                        # 无包级循环，由 TWU 驱动
  loop_exit_act: 1                   # 执行完后触发 CSU 中断

[ 流中部 ]
TWU_CONFIG_BLOCK
  Input_TWU_0 (输入特征图, 3 层 + 双缓冲)
  Input_TWU_1 (权重, 3 层)
  Output_TWU  (结果, 3 层 + 双缓冲)

[ 流后部 ]
FUNCTION_CFG (TCU_CONV2D)
  M=1024  K=432  N=64  kernel=3x3  stride=1  pad=1  dtype=bf16
```

### 11.2 底层物理运行轨迹

1. **CSU 接收并解析包头部**，SU 挂起流水线，等待 `SV_5`。
2. 外部 DMA 搬完第一块数据到 HBSM 缓冲区 A，**点亮 `SV_5`**。
3. SU 放行，TWU 开始根据嵌套循环配置生成物理地址。
4. TCU 根据 TWU 生成的地址，持续从 HBSM 缓冲区 A 读取数据进行第一次卷积计算。
5. 当 TCU 执行到特定外层循环边界时，TWU **自动将地址基址切换为 `Buffer_Offset`**（切到缓冲区 B）。
6. 在此无缝切换瞬间，DTDU 利用总线空闲，**提前将下一批数据搬到缓冲区 A**（双缓冲优势）。
7. TWU 遍历完所有地址，计算完成。
8. SU 检测到 TWU 所有循环层级的 Final 条件满足，触发 CSU 发送**硬件中断**通知外部 RISC-V 核。

### 11.3 时序图

```
Clk  │ SV_5 │  TWU 走步(A)  │ TCU 计算(A) │ buf 切换 │ TWU 走步(B) │ TCU 计算(B) │ INT
─────┼──────┼──────────────┼─────────────┼──────────┼─────────────┼─────────────┼────
     │  _/‾ │              │             │          │             │             │
     │      │ ████████████  │  ████████   │          │             │             │
     │      │              │             │  buf↑   │ ████████████ │  ████████   │
     │      │              │             │          │             │             │  _/‾
     │      │   (DTDU 搬入 B) │           │  (DTDU 搬入 A)          │             │
```

## 12. 中断、错误与调试

### 12.1 中断路径

- **紫线（Violet Line）**：TPB → 外部 RISC-V 核的专用中断线。
- 触发条件：`loop_exit_act` 含 `CSU_INT` 位，且 TWU 所有层触顶。

### 12.2 错误处理

| 错误码 | 含义 | 恢复动作 |
|--------|------|----------|
| `TWU_ERR_OVF` | 计数器溢出（Final 超范围） | 冻结走步，发中断，丢弃包 |
| `TWU_ERR_ADDR` | 生成地址越界（HBSM 范围外） | 冻结，发中断 |
| `SU_ERR_SV_TIMEOUT` | 信号量等待超时 | 重试或上报 |
| `FC_ERR_CFG` | FUNCTION_CFG 非法（维度不匹配） | 解析阶段即报错，不启动 TWU |

### 12.3 调试路径

- 每个 TPB 有**调试影子寄存器**：`twu_cnt[l]`（各层当前计数）、`twu_buf_sel`、`twu_last_addr`。
- 支持**单步走步模式**：每次迭代暂停，供仿真/驱动调试。
- 支持**地址轨迹回放**：TWU 生成的地址序列可经 trace 端口导出。

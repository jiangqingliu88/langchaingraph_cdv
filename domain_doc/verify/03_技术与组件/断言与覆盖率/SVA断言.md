# 写一条有价值的断言

> **一句话**：一条断言的价值 = 它**能失败**的概率 × 它失败时**说明的事**有多大。
> 数量毫无意义 —— 一条永远不 fail 的断言不是「通过」，是**假信心**：
> 它让你以为这里被验证过了，实际上什么都没验证。

## 适用场景

- 给协议接口 / 内部不变量写 SVA
- 断言集写完了，要确认它们「是活的」
- 评审形式验证 / ABV 的断言集，判断哪些是摆设

## 不适用

| 你实际想干的事 | 该去哪 |
|---|---|
| 决定该覆盖哪些取值组合 | `功能覆盖率建模.md` |
| 跑形式工具、读工具报出的 counterexample | `../../../verify/04_工具与脚本/JasperGold/` |
| 规划 ABV 路线、断言覆盖率目标 | `../../../verify/02_验证方法学/形式验证/` |

**为什么要分开**：断言回答「**不允许发生什么**」，覆盖回答「**至少要发生什么**」。
两者一张卡写，最后一定是「断言当覆盖用」—— 用「没报错」代替「测到了」。

## 一、`|->` 与 `|=>`：差一个 `=`，差一个周期

| 运算符 | 名字 | 含义 | 采样 |
|---|---|---|---|
| `\|->` | 重叠蕴含（overlapped） | 前提成立时，**同一拍**后件必须成立 | 前提的**当拍** |
| `\|=>` | 非重叠蕴含（non-overlapped） | 前提成立时，**下一拍**后件必须成立 | 前提的**下一拍** |

```systemverilog
// A：req 拉高的那一拍，ack 必须同时为高（同拍握手）
assert property (@(posedge clk) req |-> ack);

// B：req 拉高后，下一拍 ack 必须为高（流水线响应）
assert property (@(posedge clk) req |=> ack);
```

**误用一：把 `|=>` 当 `|->` 用**。协议要求同拍响应的场景写成 `|=>`，
断言**永远不 fail** —— 因为它检查的是下一拍，而被检查的违约发生在当拍，它看不见。
**这类断言看起来「一直通过」，实际上一整个周期对不上都没人知道。**

**误用二：把 `|->` 当 `|=>` 用**。本该下一拍响应的写成 `|->`，
会在**每一拍都 fail**，然后被 `disable iff` 或误加的 `##1` 掩盖，最后整条断言被注释掉。

**判据**：写之前先在波形图上**手工标出**「前提成立的边沿」和「后件必须成立的边沿」，
两者之间隔几拍，就用几拍的臂。`|->` 只在「同拍」时用。

### 多拍臂：`##n`

```systemverilog
// req 后隔 2 拍到 4 拍之间必须有 ack
assert property (@(posedge clk) req |-> ##[2:4] ack);

// 用蕴涵 + 延迟不如直接用「直到」语义更清楚
assert property (@(posedge clk) req |=> ##[1:3] ack);
```

**坑**：`##[2:4]` 是**窗口**，窗口内任一拍成立即可。
如果心里想的是「恰好第 3 拍」，写成 `##[2:4]` 是错的（范围放宽了），且**放宽就永远不 fail 的边界情况**。

## 二、`$past` / `$stable`：采样看的是**采样前的历史**

**采样语义是 SVA 最容易搞错的地方**。时钟块（clocking block）或属性里，
所有信号都按**default clocking 的采样时刻**取值 —— 通常在时钟边沿前的那个稳定时刻
（`#1step`）或边沿处。

```systemverilog
// 组合逻辑里用 $past 看上一拍的值
assert property (@(posedge clk) enable |-> $past(ready));

// 保证信号稳定（比如跨时钟边界前不能抖）
assert property (@(posedge clk) valid |-> $stable(data));
```

| 函数 | 语义 | 常见误用 |
|---|---|---|
| `$past(sig)` | 上一个采样时刻 `sig` 的值，默认 1 拍前 | 用在**组合路径**上，`$past` 值无意义 |
| `$past(sig, n)` | n 拍前的值 | `n=0` 在重叠语义里容易和当拍混淆 |
| `$stable(sig)` | 等价 `sig == $past(sig)` | 用在**已被驱动但同拍变化**的信号上，永远不成立 |
| `$rose(sig)` | 采样沿上从 0 变 1 | 用来看「某一拍内」的变化，看不到中间跳变 |
| `$fell(sig)` | 采样沿上从 1 变 0 | 同上 |

**关键坑**：

1. **`$past` 在仿真起点无值**。仿真前几拍 `$past` 返回 `x`，断言可能因此**在开头误报或不报**。
   正规做法是用 `$past` 的显式复位/`$initstate` 或加 `##1` 臂绕过起始窗口。
2. **`$rose` / `$stable` 是「相邻采样点」的比较，不是「信号从未跳变」**。
   两拍之间跳两次，只要采样点上同值，`$stable` 依然成立 —— **组合毛刺看不见**。
3. **`$past` 值受 `disable iff` 影响**：禁用期间 `$past` 的历史仍被记录，
   但断言不评估。禁用结束后第一拍，`$past` 拿到的是禁用期间的值。

> **判据**：任何用 `$past` / `$stable` 的断言，先问「这个信号在采样点是稳定的吗」。
> 不稳定（组合、异步），这些函数的结果就是噪声。

## 三、`disable iff`：只在「确实无意义」时禁用

```systemverilog
assert property (@(posedge clk)
  disable iff (!rst_n)          // 复位期间：检查无意义，禁用
  req |-> ##[0:2] ack);
```

**`disable iff` 的正确用途**：整个检查在某个条件下**语义上不成立**。
典型是复位期间、时钟关闭期间、模块被 bypass 期间。

**滥用形态**：

| 滥用 | 为什么诱人 | 后果 |
|---|---|---|
| `disable iff (reset \|\| !enable \|\| mode==X)` | 「这些情况下不该检查，先禁了少报错」 | 禁用条件越加越多 → 断言永不 fail |
| 用 `disable iff` 掩盖误报 | 「报错太多，先禁了」 | 把真 bug 一起禁掉，**假信心的主要来源** |
| 忘了禁用条件而用 `##1` 跳过起始 | 「开头几拍总会误报」 | 起始窗口的问题被绕过，但禁用的前提没表达清楚 |

**判据（这条最值钱）**：如果增加一个 `disable iff` 条件后断言**再也没 fail 过**，
那你要问的不是「条件对不对」，而是「**这条断言到底在检查什么**」。
一个能用 `||` 越禁越多直到永不失败的断言，本来就是错的。

**正确的定位方式**：断言应该因为「**这个条件成立时检查无意义**」而禁用，
而不是因为「**这个条件下我发现了报错，想让它闭嘴**」。
后者要去改 DUT 或改断言（比如用 `##` 臂把采样点放到真的违约时刻）。

## 四、「一条永远不 fail 的断言是假信心」

**怎么判断一条断言是死是活 —— 三个手段**：

| 手段 | 怎么做 | 说明 |
|---|---|---|
| **mutation testing** | 故意在 DUT 注入对应违约（拉高 ack、延迟一拍），断言**必须** fail | 最直接、最可信 |
| **断言覆盖率 / 触发计数** | 工具报每条断言的 **attempt count**（前提被尝试次数） | 前提从未被触发 = 断言从未被评估 |
| **形式工具的反证** | 让工具证明「该断言的否定可达」 | 不可达 = 前提永远不成立 |

**「通过」的两种含义必须分开**：

| 报告 | 可能含义 A（好） | 可能含义 B（坏） |
|---|---|---|
| 断言从未失败 | 每次前提成立时后件都成立（**真的测了**） | 前提从未成立过（**根本没测**） |
| 断言从未失败 | —— | `disable iff` 长期为真（**被禁用了**） |

**判据**：一条断言的**触发计数为 0**，和它失败，是**同等严重的问题**。
回归报告里只看「failed = 0」是自欺 —— 要看「**evaluated = N，failed = 0，N > 0**」。

## 五、检查清单

| 检查项 | 问题 |
|---|---|
| 蕴含臂 | `\|->` / `\|=>` 的周期数在波形上手工核对过吗？ |
| 窗口 | `##[a:b]` 的窗口宽度是需求要求的吗？还是随手放宽的？ |
| `$past` | 起始 x 值处理了吗？用在稳定信号上了吗？ |
| `$stable` | 被检查的信号在采样点上确实稳定吗？ |
| `disable iff` | 每个禁用条件都是「语义无意义」，不是「想少报错」吗？ |
| 触发 | 每条断言的 attempt count > 0 吗（跑过回归确认）？ |
| 活性 | 用 mutation 验证过每类断言**会**失败吗？ |
| 覆盖 | 断言覆盖率统计了吗？只报「failed=0」不算。 |
| 命名 | 断言有 `\`uvm_error` / 标签能定位到具体场景吗？ |

## 六、坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| `\|=>` 写成 `\|->` 或反过来 | 「都是蕴含，能跑就行，工具不报错」 | 永远不 fail 或永远 fail，且**工具不会告诉你** |
| `##[a:b]` 窗口随手放宽 | 「宽一点不容易误报」 | 放宽到覆盖全部可能 = 永不失败 |
| `$past` 用在组合信号上 | 「上一拍的值我当然记得」 | 组合信号无「上一拍」概念，结果无意义 |
| `$rose` 当「信号变化」用 | 「从 0 到 1 就是跳变」 | 中间跳变（0→1→0）采样点看不见 |
| `disable iff` 条件越加越多 | 「每加一个就少一堆报错」 | 断言最终被永久禁用，回归全绿但零覆盖 |
| 只看 failed=0 就签 | 「断言全通过了」 | 根本没统计触发次数，可能是 0 触发 |
| 一条 assert 检查多个不变量 | 「省事」 | 失败时不知道哪个违了；定位成本 = 断言条数 |
| 不写 `\`uvm_error` 消息 | 「工具会报行号」 | 批量失败时无法快速分类 |

**最值钱的两条**：蕴含臂写错（静默永不失败）、`disable iff` 滥用（主动静默）——
它们共同制造同一个假象：**回归全绿，但什么都没验**。

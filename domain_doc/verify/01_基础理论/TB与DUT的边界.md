# TB 与 DUT 的边界

> **一句话**：边界不是按「代码写在哪个文件」划的，是按**责任**划的 ——
> 在硅上必须存在、丢掉就会让芯片不能用，就属于 DUT；只在验证时为了观察 / 驱动而存在，才属于 TB。

## 一、定义

- **DUT（Design Under Test）**：**会被综合成芯片**的那部分。它必须在没有 testbench 的情况下
  也能工作 —— 因为流片后不会有 TB 陪着它。
- **TB（Testbench）**：**只在验证过程存在**的那部分。它的职责是「激励 → 施加 → 观察 → 判据」，
  流片后全部消失。

**DUT 的判据（任一条成立即属 DUT）**：

| 判据 | 说明 |
|---|---|
| 流片后必须存在 | 综合 / 布局布线 / 制版时要进去的东西 |
| 丢掉它芯片就不能用 | 时钟发生、复位、上电序列、真协议逻辑 |
| 有真实外部对手 | 会和芯片外部世界交互（引脚、总线、存储器） |

**TB 的判据（任一条成立即属 TB）**：

| 判据 | 说明 |
|---|---|
| 只为「施加激励」而存在 | 序列发生器、驱动器、激励生成 |
| 只为「观察 / 判定」而存在 | reference model、scoreboard、断言、覆盖率采样 |
| 是外部世界的**模型** | 存储器模型、对端协议模型的**验证替身** |

## 二、边界（不是什么）

边界不等于：

- **不等于文件划分**。同一个文件里可以既有 DUT 模块又有 TB 模块 —— 但综合脚本要能干净地把 TB 排除。
- **不等于模块层次**。TB 可以在 DUT 之上（顶层 TB 包着 DUT），也可以和 DUT 平级（验证一个子模块时，
  它的兄弟模块可以由 TB 驱动）。
- **不等于「谁写得早」**。设计先写 DUT，验证后补 TB，但边界由责任定，不由时间定。

**关键推论**：边界一旦定错，**结论会错，而不是出错**。这是它比一般编码规范更值得单独提醒的原因。

## 三、与易混概念的区别

| 易混对 | 差在哪 |
|---|---|
| TB vs 顶层（Top） | Top 通常是「TB 的容器」：TB 在 Top 里例化 DUT，并连上时钟 / 复位。Top 属于 TB，DUT 是 Top 里的一个例化。 |
| 时钟 / 复位生成 vs 时钟 / 复位逻辑 | TB 生成**时钟源**（`clk = ~clk`）和**复位源**；DUT 若含时钟门控、复位同步器、PLL 控制，那部分**必须**在 DUT 里。混这两者是最常见的边界错误。 |
| 存储器模型 vs 存储器控制器 | 存储器本身是 TB 提供的**行为模型**；存储器控制器（地址译码、时序、刷新）是 DUT。 |
| 对端协议模型 vs 协议实现 | 验证 A 模块时，B 模块可以用 TB 里的简化模型顶替；但如果 B 模块要和 A **一起流片**，B 的真实实现就该一起进 DUT（或先验 A、再验 A+B）。 |
| 断言 vs 检查逻辑 | 断言（SVA）默认**属于 TB**（不综合）；若断言要在芯片内做运行时检查，那是 DUT 的一部分（安全机制），两者目的不同。 |

## 四、边界画错的两个方向

| 方向 | 表现 | 后果 |
|---|---|---|
| **功能被塞进 TB**（DUT 缺东西） | 复位序列、上电初始化、协议握手在 TB 里做完了，DUT 里没有 | 仿真全过，硅上行为与仿真**不一致** —— 因为仿真里有一段逻辑在硅上根本不存在。这是「漏测 / 假通过」 |
| **TB 的东西被塞进 DUT**（DUT 多了东西） | 把激励生成器、scoreboard、观测逻辑综合进 RTL | 面积功耗被验证代码吃掉，且**综合可能失败**（TB 常用不可综合构造）。这是「假测 / 污染设计」 |

> 两个方向的代价不对称但要命：往 TB 塞是**假通过**（最危险，因为看起来全绿），
> 往 DUT 塞是**假设计**（会立刻被综合或面积报出来，反而容易被发现）。

## 五、典型归属速查

| 功能 | 归属 | 备注 |
|---|---|---|
| 时钟源（`always #5 clk=~clk`） | TB | 硅上有 PLL / 外部晶振，不是这样生成的 |
| 复位**源**（TB 拉复位） | TB | 复位**同步化 / 去毛刺 / 复位序列逻辑**在 DUT |
| 激励序列生成 | TB | 序列发生器 / driver |
| 参考模型 / scoreboard | TB | 判据来源，不可综合 |
| 覆盖率采样、断言 | TB | 默认不综合 |
| 存储器 / 外设**行为模型** | TB | 真实存储器在片外，行为模型是替身 |
| 协议**实现**（状态机、握手） | DUT | 芯片要真做这件事 |
| 时钟门控 / 电源开关控制 | DUT | 低功耗逻辑必须在设计里（见 `design/03_低功耗与UPF/`） |
| 复位同步器 / CDC 同步器 | DUT | 跨时钟域是真实硬件问题（见 `design/04_DFT_CDC_安全/`） |
| 测试模式选择（DFT 的 scan enable 等） | DUT | 扫描链是真实硬件 |
| 寄存器配置**接口** | DUT | 配置逻辑属于设计（见 `verify/03_技术与组件/RAL/`） |

## 六、检查清单

| 检查项 | 问题 |
|---|---|
| 综合干净 | 综合脚本能不能在不改 RTL 的情况下，把 TB 全部排除、只留 DUT？ |
| 无 TB 依赖 | DUT 的每个端口，在没有 TB 时语义完整吗（不依赖 TB 内部信号）？ |
| 无隐藏逻辑 | DUT 有没有依赖「TB 一定会先做某件事」才能工作？那件事该不该进 DUT？ |
| 时钟 / 复位归属 | 时钟源在 TB，时钟逻辑在 DUT；复位源在 TB，复位逻辑在 DUT —— 两者分清了吗？ |
| 模型替身 | 被 TB 替身的模块，和它真的一起流片吗？一起流片的话，它的实现有没有被单独验过？ |
| 可综合 | DUT 里有没有混杂不可综合构造（`initial`、`$display`、类）？ |

## 七、坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 复位序列在 TB 里做 | TB 里写状态机最方便，改起来不用动设计 | 硅上没有这个序列，DUT 上电行为与仿真不符（假通过） |
| 把激励生成器综合进 RTL | 「反正仿真能用」，省了写 TB 的力气 | 面积 / 功耗被吃，综合报错或生成垃圾逻辑 |
| 时钟门控放在 TB 里「模拟」 | 不想动设计，先在 TB 里试试断电效果 | 真正的门控逻辑没被验过，低功耗场景失效（应见 `design/03_低功耗与UPF/`） |
| reference model 用了 DUT 内部信号 | 直接抄 DUT 中间结果当期望值 | 判据和被测对象同源 → 永远判对，scoreboard 变成摆设 |
| 断言当作 DUT 内检查 | 「断言能抓错就行」 | 仿真里断言不综合，硅上没有 —— 需要芯片内自检时是另一套设计（安全机制） |
| 一个「顶层」既是 TB 又含可综合逻辑 | 图省事，一个文件全包 | 综合边界模糊，割不干净，签核时说不清哪部分上了硅 |

## 出处

- 「DUT 必须能脱离 TB 独立存在」是综合与验证分工的基本前提，各厂商仿真 / 综合流程文档
  与 DV 方法学著作表述一致。
- 本卡只写**边界判据**。**TB 内组件怎么搭** → `verify/03_技术与组件/UVM组件/`；
  **验证环境整体分层** → `verify/02_验证方法学/UVM/`；**低功耗 / CDC 的设计侧实现** →
  `design/03_低功耗与UPF/`、`design/04_DFT_CDC_安全/`。

# 低速接口（SPI / I2C / UART / JTAG）

> **一句话**：这四者都没有共享时钟意义上的"对齐"，信息藏在**边沿、位序和帧边界**里。
> 所以验证的核心不是"握手组合"，而是**采样沿选对没有、帧边界在哪、出错后能不能恢复**。

## 一、四协议的本质差异

| 维度 | SPI | I2C | UART | JTAG |
|---|---|---|---|---|
| 拓扑 | 主从，片选选从 | 多主多从，地址寻址 | 点对点 | TAP 状态机链 |
| 时钟 | 独立 SCLK（随数据） | 独立 SCL（开漏，可被从机拉长） | **无时钟**（双方约定波特率） | 独立 TCK |
| 线数 | 4（CS/SCLK/MOSI/MISO） | 2（SDA/SCL） | 2（TX/RX） | 4/5（TCK/TMS/TDI/TDO/TRST） |
| 帧边界 | CS 拉低到拉高 | START / STOP 条件 | 起始位+数据+奇偶+停止位 | TAP 状态机状态转移 |
| 应答机制 | 无（协议层不管） | ACK / NACK 每字节 | 无（可选奇偶校验） | 无（靠状态机） |
| 从机反压 | 无（主控全部时序） | **时钟拉伸**（从机拉低 SCL） | 无（靠流控线如 RTS/CTS，可选） |

**关键**：SPI 是"主控一切"（主给时钟，从无发言权）；I2C 有从机时钟拉伸，是唯一在
本地就带反压语义的；UART 完全靠双方波特率自洽；JTAG 是状态机驱动的命令链。

## 二、信号与时序语义

### 2.1 SPI：模式（CPOL / CPHA）决定采样沿

| 模式 | CPOL | CPHA | 采样沿 | 移位沿 |
|---|---|---|---|---|
| Mode 0 | 0 | 0 | 上升沿 | 下降沿 |
| Mode 1 | 0 | 1 | 下降沿 | 上升沿 |
| Mode 2 | 1 | 0 | 下降沿 | 上升沿 |
| Mode 3 | 1 | 1 | 上升沿 | 下降沿 |

**SPI 最大的坑**：主从模式配错时，数据不是"错位一格"而是**整体移位一个 bit**——
因为采样沿和移位沿反了。所以"采样沿选对没有"必须是显式覆盖项。

### 2.2 I2C：START / STOP / ACK 是电平条件

- START：SCL 高时 SDA 由高变低
- STOP：SCL 高时 SDA 由低变高
- 数据位：SCL 高电平期间 SDA 必须**稳定**，只在 SCL 低时变化
- ACK：接收方在第 9 个 SCL 周期把 SDA 拉低
- **时钟拉伸**：从机把 SCL 拉低即暂停，主机必须等待

### 2.3 UART：帧结构 = 起始 + 数据 + 可选校验 + 停止

- 起始位（低）→ 数据位（LSB first，5–9 位）→ 可选奇偶位 → 停止位（高，1/1.5/2）
- **无共享时钟**：双方各自用本地时钟按波特率采样，误差累积决定帧完整性
- **过采样**：接收方通常以 16x 波特率采样，在中间采样点取位（这一条决定了"噪声容忍"）

### 2.4 JTAG：TAP 状态机

- TMS 在 TCK 上升沿被采样，驱动 16 状态的状态机（Test-Logic-Reset → Run-Test/Idle → …）
- 数据在 TDI→TDO 之间经移位寄存器，按 IR（指令寄存器）/ DR（数据寄存器）分别移位
- **TMS 序列 = 状态转移路径**，任何一条路径都由一连串 TMS 值决定

## 三、合法 / 非法组合

| 协议 | 组合 | 合法性 | 该不该验 |
|---|---|---|---|
| SPI | 主从 CPOL/CPHA 一致 | 合法 | 必验全 4 种模式 |
| SPI | CS 在传输中途拉高 | **非法**（帧被截断） | 必验；从机行为需定义 |
| SPI | CS 未拉低就有 SCLK | **非法** | 断言 |
| I2C | SCL 高时 SDA 变化（非 START/STOP） | **非法** | 断言 |
| I2C | 无 ACK（主机收到 NACK） | 合法 | 必验（设备未响应） |
| I2C | 从机时钟拉伸 | 合法 | 必验——常被漏 |
| I2C | 仲裁丢失（多主同发） | 合法 | 多主系统必验 |
| UART | 停止位缺失（帧错误） | 语义为错误 | 必验——接收方应报 framing error |
| UART | 波特率偏差超容忍 | 语义为错误 | 必验——边界偏差 |
| UART | 奇偶校验错 | 语义为错误 | 必验 |
| JTAG | 非法状态转移 | **结构性约束** | 由状态机保证；断言兜底 |
| JTAG | 复位期间 TMS 保持 | 合法（进 TAP reset） | 必验 |

**规律**：SPI / I2C 的违规是**协议违规**（应被断言挡住）；UART 的"错误"是**合法但异常的
接收结果**（应该被正确报告，不是违规）—— 两者要用不同的检查手段，别混。

## 四、检查点

| 层级 | 检查点 | 手段 |
|---|---|---|
| 位级 | 采样沿（SPI 模式）/ 采样点（UART 中点）正确 | 断言 + 定向时序用例 |
| 位序 | LSB / MSB first 正确 | 定向用例 |
| 帧边界 | 起始 / 结束条件识别正确 | 断言 |
| 应答 | I2C ACK/NACK 生成与判别、SPI 无应答语义 | scoreboard |
| 反压 | I2C 时钟拉伸被正确等待 | 定向用例 + 断言 |
| 错误报告 | UART framing / parity / overrun error 上报 | scoreboard + 中断检查 |
| 恢复 | 错误后能回到空闲、能重新同步 | 定向用例 |
| 状态机 | JTAG TAP 转移路径正确 | 断言 / 形式 |

## 五、VIP 怎么接（通用做法）

| 协议 | 通用接法 |
|---|---|
| SPI | master agent 驱动 SCLK/CS/MOSI、采样 MISO；**模式做成配置项**，别写死一种 |
| I2C | agent 需实现开漏语义与时钟拉伸；多主场景要能模拟仲裁 |
| UART | agent 用过采样时钟，错误可**注入**（人为破坏一位、改波特率）以验接收方错误处理 |
| JTAG | BFM 按 TMS 序列驱动状态机，按 IR/DR 组织命令；常与 SoC 调试需求联动 |

**通用原则**：低速接口的 VIP，重点不在事务级 scoreboard，而在于**能注入位级错误**
（改一位、改时序、改波特率）——因为这类接口的 bug 大多在错误处理的边界上。

## 六、能写出它的 coverpoint

| 协议 | 覆盖维度 |
|---|---|
| SPI | 模式（CPOL×CPHA 4 种）、帧长（8/16/32）、CS 时序（传输中插入空闲）、多从片选切换、时钟速率 |
| I2C | START/STOP、ACK/NACK、时钟拉伸（无/有/最长）、7 位 vs 10 位地址、广播地址、仲裁丢失 |
| UART | 数据位宽（5–9）、停止位（1/1.5/2）、奇偶（无/奇/偶）、波特率（含边界偏差）、错误类型（framing/parity/overrun） |
| JTAG | TAP 状态（全 16 态）、IR/DR 长度、复位路径、多器件链（IR 串联长度） |

```systemverilog
// I2C 覆盖点方向
cp_cond  : coverpoint cond { bins start = {START}; bins stop = {STOP}; bins data = {DATA}; }
cp_ack   : coverpoint ack  { bins ack = {ACK}; bins nack = {NACK}; }
cp_stretch: coverpoint stretch { bins none = {0}; bins short = {[1:8]}; bins long = {[9:$]}; }
X_cond_ack: cross cp_cond, cp_ack;   // 每个字节位置的 ACK/NACK

// UART 覆盖点方向
cp_baud  : coverpoint baud { bins exact = {0}; bins neg_edge = {-3}; bins pos_edge = {3}; }
cp_frame : coverpoint frame_err { bins none = {0}; bins framing = {FRAMING};
                                  bins parity = {PARITY}; bins overrun = {OVERRUN}; }
```

## 七、坑

| 坑 | 为什么诱人 | 修正 |
|---|---|---|
| SPI 只验一种模式 | 项目里就用了 Mode 0 | 从设备可能被配成任意模式，四种都要覆盖 |
| 把 UART 的 framing error 当协议违规 | "看到错误就该报" | 它是合法接收结果，应被上报，不是断言失败 |
| I2C 忘了时钟拉伸 | 单主、无慢从机的理想场景跑得通 | 拉伸是最常被漏的反压路径 |
| 波特率只按标称值验 | 标称值最好配 | 偏差累积到帧尾才暴露，要测边界偏差 |
| SPI 模式配错靠"看数据"发现 | 数据看着像对的 | 整体移一位的数据常被误读为正确 |
| JTAG 只验复位不验转移路径 | 复位最容易 | 有效命令依赖完整 TMS 序列，路径错就进不了目标态 |
| 错误注入不做 | 正常帧全过就收工 | 低速接口的价值常在于错误处理 |

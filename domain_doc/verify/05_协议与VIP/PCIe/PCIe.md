# PCIe

> **一句话**：PCIe 把"一个请求从 A 到 B"拆成三层各自负责一段：事务层管**语义与顺序**，
> 数据链路层管**可靠传输（重传）**，物理层管**位流与链路**。验 PCIe 的难点不在某一层，
> 而在**跨层的交互**——流控信用与重传、排序与完成。

## 一、分层结构

| 层 | 处理的单元 | 职责 | 排序/可靠性的归属 |
|---|---|---|---|
| 事务层 Transaction Layer | TLP | 生成/解析请求与完成、属性、排序、流控信用管理 | **排序规则在这里** |
| 数据链路层 Data Link Layer | DLLP | ACK/NAK、序列号、重传、错误检测（LCRC） | **可靠传输在这里** |
| 物理层 Physical Layer | Ordered Set / Symbol | 编码、链路训练、lane 管理、弹性缓冲 | 位级链路 |

**分层验证的意义**：一个"数据丢了"的现象，根因可能在事务层排序、链路层重传、或物理层
训练——**先定层，再定检查点**，否则会在大海捞针地看波形。

## 二、TLP 类型（事务层）

| 类别 | TLP 类型 | 语义 |
|---|---|---|
| 存储器 | MemRd / MemWr | 读写内存空间（最常见） |
| IO | IORd / IOWr | 读写 IO 空间（遗留） |
| 配置 | CfgRd0/1 / CfgWr0/1 | 读写配置空间（Type0=Endpoint，Type1=Bridge） |
| 消息 | Msg / MsgD | 中断、电源管理、错误上报等 |
| 完成 | Cpl / CplD | 对非转发请求的响应，可带数据 |

**TLP 头部关键字段（语义，不涉具体位编码）**：
- 请求者/完成者标识、Tag（区分同源的多个未完成请求）、Traffic Class
- 属性位：缓存一致性提示、顺序提示
- **Fmt / Type**（决定 TLP 种类与是否带数据）
- 长度字段（数据负载单位与字节数）
- 每层各挂一个校验（事务层摘要 / 链路层 LCRC）

> 具体字段位段与编码见 PCI-SIG 规范对应章节，本卡只给语义——**别凭记忆默写位域**。

## 三、两个必须分清的机制

### 3.1 流量控制（Flow Control）：信用制，不是握手

发送方**预先**从接收方获得信用（credit），按**每一类**（Posted / Non-Posted 的 Header
与 Data）分别计数。发一包扣一种信用，收到 Flow Control Update DLLP 才补回。

| 线索 | 含义 |
|---|---|
| 信用分类 | Posted / Non-Posted，各分 Header / Data |
| 为什么要分类 | 不同类别不能被别人的信用"借用" |
| 常见 bug | 只扣不补 / 补错类别 / 初始信用耗尽后死锁 |

### 3.2 排序规则（Ordering）：完成与请求的可见性

排序规则规定了不同类型的 TLP 能否相互"超车"。**强顺序**（如强制的读写顺序提示）
与**弱顺序/宽松顺序**要分别建模。排序规则是**性能与正确性的取舍点**：
越宽松越快，越容易出可见性问题。

### 3.3 可靠传输：ACK/NAK 与重传

| 机制 | 说明 |
|---|---|
| 序列号 | 每个 TLP 编号，接收方按序列号检测有无丢失 |
| ACK DLLP | 接收方确认已收到 |
| NAK DLLP | 接收方要求重传（校验失败或序号缺失） |
| 重传缓冲 | 发送方保留已发未确认的 TLP |

## 四、合法 / 非法组合

| 组合 | 合法性 | 该不该验 |
|---|---|---|
| 发送方信用耗尽后仍发同类 TLP | **非法** | 断言——这是流控的核心约束 |
| 收到 NAK 后重传，序列号正确 | 合法 | 必验 |
| 收到校验失败的 TLP：丢弃并 NAK | 合法（规定行为） | 必验——错误注入 |
| Cpl 与请求 Tag 对不上 | **非法**（孤儿完成） | 断言 + scoreboard |
| 弱顺序下完成先于数据可见 | 合法 | 必验——它正是顺序提示的意义 |
| 强顺序被违反 | **非法** | 断言 |
| 重传缓冲区溢出 | **非法** | 断言 |
| 超时未收到 Cpl | 合法但异常 | 必验——超时处理与恢复 |

## 五、检查点

| 层 | 检查点 | 手段 |
|---|---|---|
| 事务层 | TLP Fmt/Type 与长度自洽 | 断言 |
| 事务层 | Tag 唯一性（未完成请求的 Tag 不重用） | 断言 |
| 事务层 | 排序规则：强顺序不被违反 | 断言 |
| 事务层 | 完成与请求配对（无孤儿、无悬挂） | scoreboard |
| 链路层 | 序列号连续、无重复、无缺失 | 断言 |
| 链路层 | ACK/NAK 与重传缓冲一致 | scoreboard |
| 链路层 | LCRC / 错误检测 | 断言 + 错误注入 |
| 链路层 | 流控信用：扣减与补回严格配平 | 断言 |
| 物理层 | 链路训练、lane 协商、弹性缓冲不溢出 | 断言 / 专项用例 |
| 端到端 | 配置访问、枚举、中断投递 | scoreboard |

## 六、VIP 怎么接（通用做法）

| 部件 | 通用接法 |
|---|---|
| Root Complex / Endpoint VIP | 一侧当对端，模拟真实链路行为 |
| 分层检查器 | **每层独立一个协议检查器**，别揉成一个 |
| 流控与重传 | VIP 需能注入：丢包、坏 CRC、信用延迟更新 |
| 错误注入 | 能造出 NAK、超时、畸形 TLP，验证错误处理路径 |
| scoreboard | 按 Tag 分桶配对请求/完成；跨层关联（事务层请求 ↔ 链路层 TLP） |

**通用原则**：PCIe 的验证价值集中在**负向路径**——正常转发很难错，错的是重传、
信用、排序、超时这些边界。VIP 若不能注入错误，等于只验了一半。

## 七、能写出它的 coverpoint

| 层级 | 覆盖维度 |
|---|---|
| 事务层 | TLP 类型（Mem/IO/Cfg/Msg/Cpl）、长度（最小/典型/最大）、Tag 复用、TC、属性位组合 |
| 排序 | 顺序提示组合（强/弱）、完成与请求的相对顺序 |
| 流控 | 四类信用各自耗尽 / 部分 / 富余；信用更新时机 |
| 链路层 | 序列号回绕、ACK/NAK 比例、重传次数（0/1/多）、重传缓冲满 |
| 物理层 | 链路宽度（x1/x4/x8/x16）、速率、训练路径 |
| 错误 | 校验错、超时、畸形 TLP、孤儿完成 |

```systemverilog
// 事务层覆盖点方向
cp_tlp   : coverpoint tlp_type { bins mem = {MEM}; bins cfg = {CFG};
                                 bins msg = {MSG}; bins cpl = {CPL}; }
cp_len   : coverpoint length { bins min = {1}; bins max = {MAX}; bins mid = {[2:MAX-1]}; }
cp_order : coverpoint ordering { bins strong = {STRONG}; bins weak = {WEAK}; }
X_tlp_len_order: cross cp_tlp, cp_len, cp_order;

// 链路层覆盖点方向
cp_cfc   : coverpoint credit { bins ample = {AMPLE}; bins tight = {TIGHT}; bins empty = {EMPTY}; }
cp_retry : coverpoint retry  { bins none = {0}; bins once = {1}; bins multi = {[2:$]}; }
```

## 八、坑

| 坑 | 为什么诱人 | 修正 |
|---|---|---|
| 只在"链路完美"下验 | 不丢包、不重传，跑得最快 | 不注入错误的 PCIe 验证只覆盖了正常转发 |
| 流控信用只扣不验补 | 补回路径正确性难观察 | 必须验"扣减与补回严格配平" |
| 排序规则只验强顺序 | 强顺序最容易断言 | 弱顺序/顺序提示才是性能与可见性的取舍点 |
| 把"仿真过了"当"链路可靠" | 仿真里链路无随机位错 | 可靠性来自 ACK/NAK 与重传机制，要注入位错 |
| 完成与请求不配对 | 只对数据不对归属 | 孤儿完成、悬挂请求都要被 scoreboard 抓 |
| 各层检查器揉成一个 | 少写代码 | 分层检查才能**定位**问题在哪层 |
| 凭记忆写 TLP 位域 | 觉得自己记得 | 必须查 PCI-SIG 规范，位域默写是重灾区 |

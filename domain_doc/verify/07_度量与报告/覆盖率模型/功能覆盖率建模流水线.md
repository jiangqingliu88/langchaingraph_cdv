# 功能覆盖率建模流水线（YAML 作 IR）

> **YAML 是中间表示（IR）。九步法把模块推导成 YAML，纯函数把 YAML 生成覆盖率文件。
> LLM 只用在「模块 → YAML」，其余全是确定性生成。**

```
模块（RTL/规格/接口）
    ↓ [点状 LLM + 九步法]
coverage_plan.yaml          ← 人可读、机器可校验、可追溯
    ↓ [纯函数] schema 校验
coverage_plan.validated.yaml
    ↓ [纯函数] 模板引擎
coverage_model.sv           ← SystemVerilog covergroup
    ↓ [仿真]
coverage.ucdb / .vdb        ← 覆盖率数据库
    ↓ [纯函数] 解析
coverage_report.yaml        ← 覆盖率结果
```

**关键：只有第一步用 LLM，后面全是纯函数。这是可复现、可审计的根基。**

> ⚠️ **与其他卡的关系**：本卡描述的是**流水线**（数据怎么流、哪一步是谁）。
> 覆盖点本身怎么推导见 `KB-DV-COV-001`；**另有一份不同的 YAML 设计稿**见
> `KB-DV-COV-002`（那份用 `coverpoints/crosses/constraints/batches`，本卡用
> `signals/covergroups/system_scenarios/nonfunctional/meta_checks`）—— 两者是
> **两套备选设计**，都不是本仓库在跑的格式。本仓库的实际链路见
> `src/tools/casemodel_tools/readme.md`。

## 触发条件

- 覆盖率模型要能**重复生成**（换个人、换台机器，输出一致）
- 覆盖率要能**审计**（每个 bin 的命中数、waiver、审批人可追）
- 模型与「跑出来的结果」要能对账，而不是散在两份文档里

## 各阶段：谁做、准入、准出、制品

| 阶段 | 谁做 | 准入 | 准出 | 制品 |
|---|---|---|---|---|
| 解析模块 | 纯函数 | 拿到 RTL / 规格 / 接口 | 三者可读 | 模块信息 |
| **推导 YAML** | **点状 LLM** | 模块信息 + schema | 过了 schema 与追溯校验 | `coverage_plan.yaml` |
| 校验 | 纯函数 | YAML 已生成 | schema / 追溯 / cross 爆炸三项无错 | `.validated.yaml` |
| 生成 SV | 纯函数 | 校验通过 | 模板渲染成功 | `coverage_model.sv` |
| 仿真采样 | Agent | SV 可编译 | 覆盖率库落盘 | `.ucdb` / `.vdb` |
| 解析结果 | 纯函数 | 库存在 | 结构化成报告 | `coverage_report.yaml` |
| 缺口分类 | 纯函数 | 报告已解析 | 每个缺口有原因 | 缺口清单 |
| 反哺 | 纯函数 | 缺口已分类 | 计划更新 | 新 `coverage_plan.yaml` |

**准入/准出是这条链的全部价值**：任何一段「看着过了其实没过」，后面的数字都不可信。

## 一、YAML Schema 设计

YAML 必须能完整表达九步法的所有维度。下面是完整 schema。

### 1.1 顶层结构

```yaml
# coverage_plan.yaml
meta:
  module: fifo_ctrl
  version: "1.0"
  rtl: rtl/fifo_ctrl.sv
  spec: docs/fifo_spec.md
  clock: clk
  reset: rst_n

requirements: [...]      # 需求追溯
signals: [...]           # 第1-2步：信号与取值
covergroups: [...]       # 第3-7步：组合、时序、并发
system_scenarios: [...]  # 第7步：系统级
nonfunctional: [...]     # 第8步：非功能
meta_checks: [...]       # 第9步：元维度
```

### 1.2 完整 Schema 定义

```yaml
# schema 关键字段
signals:
  inputs:
    - name: <string>          # 信号名
      width: <int>            # 位宽
      values:                 # 第2步：取值分类
        normal: [...]         # 正常值
        boundary: [...]       # 边界值
        special: [...]        # 特殊值
        illegal: [...]        # 非法值
  outputs:
    - name: <string>
      width: <int>

covergroups:
  - name: <string>            # covergroup 名
    clock: <string>
    reset: <string>
    coverpoints:
      - name: <string>        # coverpoint 名
        expr: <string>        # 采样表达式
        bins:
          <bin_name>:
            type: value | range | transition | sequence | cross
            values: [...]
        illegal_bins: [...]
        ignore_bins: [...]
    crosses:
      - name: <string>
        items: [cp1, cp2, ...]
        bins:                 # 只交叉有意义的组合
          <bin_name>:
            cp1: <bin>
            cp2: <bin>

system_scenarios:             # 第7步
  - name: <string>
    desc: <string>
    coverpoint: <string>

nonfunctional:                # 第8步
  - name: <string>
    type: latency | throughput | fairness | power | cdc | error_inject
    bins: [...]

meta_checks:                  # 第9步
  - name: <string>
    type: reachability | unreachability | mutation | redundancy
```

## 二、完整 YAML 示例（以 FIFO 为例）

```yaml
# coverage_plan.yaml
meta:
  module: fifo_ctrl
  version: "1.0"
  rtl: rtl/fifo_ctrl.sv
  spec: docs/fifo_spec.md
  clock: clk
  reset: rst_n

requirements:
  - id: REQ-FIFO-001
    desc: FIFO 满时写入应返回错误
    method: simulation
    coverage_type: functional
  - id: REQ-FIFO-002
    desc: FIFO 空时读取应返回阻塞
    method: simulation
    coverage_type: functional
  - id: REQ-FIFO-003
    desc: 同时读写应正确处理
    method: simulation
    coverage_type: functional

signals:
  inputs:
    - name: wr_en
      width: 1
      values:
        normal: [0, 1]
    - name: rd_en
      width: 1
      values:
        normal: [0, 1]
    - name: level
      width: 4
      values:
        normal: [1, 2, 3, 4, 5, 6, 7]
        boundary: [0, 15]
        special: []
  outputs:
    - name: full
      width: 1
    - name: empty
      width: 1
    - name: result
      width: 2
      values:
        normal: [0]        # OK
        special: [1, 2]    # BLOCKED, ERROR

covergroups:
  - name: cg_fifo
    clock: clk
    reset: rst_n
    coverpoints:
      # 第2步：信号取值
      - name: cp_level
        expr: level
        bins:
          empty: { type: value, values: [0] }
          low:   { type: range, values: [[1, 3]] }
          mid:   { type: range, values: [[4, 7]] }
          full:  { type: value, values: [15] }
        illegal_bins: []
        ignore_bins:
          - name: during_reset
            expr: rst_n == 0

      - name: cp_op
        expr: "{wr_en, rd_en}"
        bins:
          both: { type: value, values: [3] }
          wr:   { type: value, values: [2] }
          rd:   { type: value, values: [1] }
          none: { type: value, values: [0] }

      - name: cp_result
        expr: result
        bins:
          success: { type: value, values: [0] }
          blocked: { type: value, values: [1] }
          error:   { type: value, values: [2] }

    crosses:
      # 第3步：信号组合
      - name: x_level_op_result
        items: [cp_level, cp_op, cp_result]
        bins:
          full_write_blocked:
            cp_level: full
            cp_op: wr
            cp_result: blocked
          empty_read_blocked:
            cp_level: empty
            cp_op: rd
            cp_result: blocked
          full_both_blocked:
            cp_level: full
            cp_op: both
            cp_result: blocked

system_scenarios:
  - name: sc_fifo_to_dram
    desc: FIFO 满时向 DRAM 写入
    coverpoint: cp_fifo_dram
  - name: sc_dram_to_fifo
    desc: DRAM 向 FIFO 读取
    coverpoint: cp_dram_fifo

nonfunctional:
  - name: cp_latency
    type: latency
    bins:
      min_lat: { type: value, values: [1] }
      typical: { type: range, values: [[2, 8]] }
      long_lat: { type: range, values: [[9, 100]] }
  - name: cp_throughput
    type: throughput
    bins:
      idle:   { type: value, values: [0] }
      low:    { type: range, values: [[1, 2]] }
      peak:   { type: value, values: [16] }

meta_checks:
  - name: reach_full
    type: reachability
    target: cg_fifo.cp_level.full
  - name: unreach_illegal
    type: unreachability
    target: cg_fifo.illegal_bins
```

## 四、YAML → 覆盖率文件：纯函数生成

这一步**不用 LLM**，用模板引擎（Jinja2）把 YAML 生成 SystemVerilog covergroup。

### 4.1 Jinja2 模板

```jinja2
{# templates/covergroup.sv.j2 #}
// 自动生成，请勿手改
// 来源: {{ meta.module }} v{{ meta.version }}
// 生成时间: {{ generated_at }}

{% for cg in covergroups %}
covergroup {{ cg.name }} @(posedge {{ cg.clock }});
  option.per_instance = 1;
  {% if cg.reset %}
  option.name = "{{ cg.name }}";
  {% endif %}

  {% for cp in cg.coverpoints %}
  {{ cp.name }}: coverpoint {{ cp.expr }} {
    {% for bin_name, bin in cp.bins.items() %}
    {% if bin.type == "value" %}
    bins {{ bin_name }} = { {% for v in bin.values %}{{ v }}{% if not loop.last %}, {% endif %}{% endfor %} };
    {% elif bin.type == "range" %}
    bins {{ bin_name }} = { {% for r in bin.values %}[{{ r[0] }}:{{ r[1] }}]{% if not loop.last %}, {% endif %}{% endfor %} };
    {% elif bin.type == "transition" %}
    bins {{ bin_name }} = ({% for s in bin.values %}{{ s }}{% if not loop.last %} => {% endif %}{% endfor %});
    {% endif %}
    {% endfor %}
    {% for ib in cp.illegal_bins %}
    illegal_bins {{ ib.name }} = {{ ib.expr }};
    {% endfor %}
    {% for ig in cp.ignore_bins %}
    ignore_bins {{ ig.name }} = {{ ig.expr }};
    {% endfor %}
  }
  {% endfor %}

  {% for x in cg.crosses %}
  {{ x.name }}: cross {{ x.items | join(", ") }} {
    {% for bin_name, bin in x.bins.items() %}
    bins {{ bin_name }} = {% for cp_name, cp_bin in bin.items() %}binsof({{ cp_name }}.{{ cp_bin }}){% if not loop.last %} && {% endif %}{% endfor %};
    {% endfor %}
  }
  {% endfor %}
endgroup
{% endfor %}
```

### 4.2 生成器（Python 纯函数）

```python
import yaml
from jinja2 import Template
from datetime import datetime, timezone

def generate_covergroup(yaml_path: str, template_path: str) -> str:
    """
    从 YAML 生成 SystemVerilog covergroup。
    纯函数：同样输入 → 同样输出。
    """
    with open(yaml_path) as f:
        plan = yaml.safe_load(f)

    with open(template_path) as f:
        template = Template(f.read())

    # 只取必要字段，保证确定性
    context = {
        "meta": plan["meta"],
        "covergroups": plan["covergroups"],
        "generated_at": "DO_NOT_USE_TIMESTAMP",  # 不写时间戳，保证可复现
    }

    return template.render(**context)


def generate_coverage_pkg(yaml_path: str, output_path: str):
    """
    生成完整覆盖率文件，包括：
    1. covergroup 定义
    2. 实例化
    3. 采样逻辑
    """
    sv = generate_covergroup(yaml_path, "templates/covergroup.sv.j2")

    with open(output_path, "w") as f:
        f.write(sv)

    return output_path
```

## 五、校验、结果解析与缺口分类（全部纯函数）

### 5.3 校验器（纯函数）

```python
import jsonschema

def validate_coverage_yaml(yaml_path: str, schema_path: str) -> dict:
    """
    纯函数校验：schema + 完整性 + 可追溯性。
    返回：{"valid": bool, "errors": [...]}
    """
    with open(yaml_path) as f:
        plan = yaml.safe_load(f)
    with open(schema_path) as f:
        schema = yaml.safe_load(f)

    errors = []

    # 1. schema 校验
    try:
        jsonschema.validate(plan, schema)
    except jsonschema.ValidationError as e:
        errors.append(f"schema: {e.message}")

    # 2. 需求追溯：每个 coverpoint 必须追溯到需求
    req_ids = {r["id"] for r in plan.get("requirements", [])}
    for cg in plan.get("covergroups", []):
        for cp in cg.get("coverpoints", []):
            if "req" not in cp:
                errors.append(f"{cg['name']}.{cp['name']} 未追溯到需求")

    # 3. cross 爆炸检查
    for cg in plan.get("covergroups", []):
        for x in cg.get("crosses", []):
            n_bins = len(x.get("bins", {}))
            if n_bins > 100:
                errors.append(f"{x['name']} bin 数 {n_bins} 过多，可能爆炸")

    # 4. 每个 bin 必须有约束能命中（需要约束求解器）
    # ...

    return {"valid": len(errors) == 0, "errors": errors}
```

## 六、闭环：从覆盖率结果回到 YAML

```yaml
# coverage_plan.yaml 追加运行结果
run_results:
  run_id: run_2026_10_12_001
  timestamp: "2026-10-12T10:00:00Z"
  coverage:
    functional: 0.95
    cross: 0.80
  gaps:
    - coverpoint: cg_fifo.x_level_op_result
      bin: empty_read_blocked
      hits: 0
      cause: random_insufficient
      action: 增加种子数 / 调整约束
  waivers:
    - bin: cg_fifo.illegal_bins
      reason: 架构不可达
      approved_by: design_lead
```

**这样，YAML 既是计划，也是运行记录，也是审计证据。**

## 七、关键设计原则

| 原则 | 做法 |
|---|---|
| **LLM 只做推导** | 模块→YAML 用 LLM，YAML→SV 用纯函数 |
| **YAML 是唯一真相** | 所有覆盖率文件从 YAML 生成，不手改 |
| **可复现** | 不写时间戳，不写随机数，同样输入同样输出 |
| **可追溯** | 需求→coverpoint→bin→test 全链路 |
| **可校验** | schema + 完整性 + 可命中性 + 不可达性 |
| **可审计** | 每个 bin 的命中数、waiver、审批人全记录 |
| **可回退** | 覆盖率不达标 → 缺口分类 → 回对应 Agent |

---

**其中三条是本卡真正的论点**：

| 原则 | 为什么 |
|---|---|
| LLM 只做推导 | 只要 LLM 参与生成，同输入就未必同输出 —— 可复现从这一步开始崩 |
| YAML 是唯一真相 | 生成物一律不手改。手改一次，YAML 与 SV 就分叉，而没人知道哪份是对的 |
| 不写时间戳 | 时间戳是「同样输入同样输出」的直接破坏者（原稿里 `DO_NOT_USE_TIMESTAMP` 就是这条） |

## 八、一句话总结

> **YAML 是中间表示，九步法把模块推导成 YAML，纯函数把 YAML 生成覆盖率文件。**
>
> - **模块→YAML**：点状 LLM，按九步法提示词生成，schema 约束
> - **YAML→SV**：纯函数，Jinja2 模板引擎，零 LLM
> - **SV→覆盖率数据库**：仿真器
> - **数据库→报告**：纯函数解析
> - **报告→缺口**：纯函数分类
> - **缺口→YAML**：反哺计划，形成闭环
>
> **LLM 只在第一步，后面全是确定性。这是可复现、可审计、可签核的根基。**

# 覆盖率计划模板

> **一句话**：覆盖率计划要能回答「**哪条需求由哪个 coverpoint 的哪个 bin、哪个用例负责**」——
> 回答不了这三层的计划，签核时就是一张废纸。

## 用途

- 新模块立覆盖率计划
- 评审一份计划：它的需求映射表是不是空的

**用法**：复制下面的模板，**每一格都填**。留空的格子会在签核时变成
「这条需求到底测了没有」的争论 —— 而那些争论没有一次是靠翻代码解决的。

## 误用示例

| 误用 | 后果 |
|---|---|
| 需求映射表只填需求不填 coverpoint | 无法回答「这条需求被哪个覆盖点看着」，签核时追溯断链 |
| 覆盖率目标只写 Functional，不写其余五类 | 结构性覆盖（FSM/Toggle/Condition）无人负责 |
| Cross 清单不估 bin 数 | 交叉爆炸到上万 bin 才发现，涨不上去 |
| `ignore_bins` 不写理由 | 后面没人敢碰，也没人知道该不该碰 |
| 测试用例映射留空 | 无法回答「这个 coverpoint 靠哪个用例打」 |

## 填空项的说明

| 项 | 怎么填 |
|---|---|
| 第 2 节 Covergroup/Coverpoint | **必须填到 coverpoint 粒度**，只填 covergroup 等于没填 |
| 第 3 节目标 | 六类都写。只写 Functional 的计划，剩下五类无人负责 |
| 第 4 节 Bin 数估算 | 估出来。**估算超 100 就该拆** —— 交叉爆炸在计划阶段就要拦 |
| 第 5 节理由 | 每条都要。「难测」不是理由，**可达性证据**才是 |
| 第 6 节种子数 | 与回归策略一致。种子数决定复现性，不是拍脑袋 |
| 第 9 节勾选项 | 与 `../../02_流程与签核/验证签核.md` 的准入清单**同源**，不要各自维护一份 |

> **最后一条是本模板唯一需要你主动维护的一致点**：计划里的签核标准与签核门的准入清单
> 是同一件事。两边各写一份，改了这边忘那边，签核时就会出现「计划说 95%、门说 100%」。

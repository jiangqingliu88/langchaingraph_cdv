# 低功耗验证

> **一句话**：低功耗验证不问「怎么切域」（那是设计的活），只问三件事 ——
> **切换对不对、断得干不干净、醒得对不对**。
> 其中最容易崩的不是时序，是**UPF 与 RTL 对不上**：仿真报错，或更坏 —— 静默不生效。

## 适用场景

- 设计含电源域（`design/03_低功耗与UPF/` 已定义域、隔离、保持），需要验它是否按预期工作
- 要写电源状态相关激励、配电源状态覆盖率
- 断电唤醒回归要跑，但要判断「醒没醒对」而不只是「没报错」

## 不适用

| 你实际想干的事 | 该去哪 |
|---|---|
| 决定电源域怎么切、隔离 / 保持加在哪、UPF 怎么写 | `design/03_低功耗与UPF/` |
| 看省了多少功耗、PPA 取舍 | `design/02_综合_时序_PPA/` |
| 验 CDC / RDC 同步器本身 | `design/04_DFT_CDC_安全/`（设计侧）与 `verify/` 对应卡 |
| 记录本次项目实测的电源覆盖数字 | `verify/06_项目案例/` |

**这条比「适用」更值钱**：设计侧讲「怎么把低功耗做出来」，验证侧讲「做出来的有没有按预期」。
两边都写会重复，还让「域怎么切」和「切完对不对」两件事都读一遍才搞懂。

## 步骤

### 第 1 步：先把电源状态表读成「可验证的对象」

UPF 里的电源状态表（PST）是验证的**唯一合法状态清单**。
拿它列出：有哪些电源域、每个域有哪些状态、哪些状态组合是合法的。

| 产物 | 说明 |
|---|---|
| 电源域 × 状态矩阵 | 每域每状态一列，标注哪些组合合法 |
| 合法状态转移图 | 上电 / 断电 / 保持 的转移条件 |
| 非法状态清单 | 协议不允许的组合 —— 要显式定义为 forbidden |

**判据**：状态表列不全，后面的覆盖率模型就没法定义「什么算测到了」。

### 第 2 步：写「切换序列」激励

电源状态切换是**多周期、带外部控制**的行为，随机约束管不到，必须写定向序列：

| 要验的切换 | 激励要做的事 |
|---|---|
| 正常上下电 | 按合法顺序拉起 / 关断各域电源 |
| 部分断电 | 只关部分域，其余保持 |
| 快速反复切换 | 相邻帧内反复上下电，抓时序边界 |
| 非法切换 | 尝试一个不合法的状态跳转，验证被拒 / 报错 |
| 掉电唤醒 | 断电 → 唤醒源触发 → 恢复，验证恢复后功能正确 |

### 第 3 步：每个切换点上查「三件事」

**电源域切换不是「电源线变了」一件事**，每个切换点要同时查：

| 检查面 | 查什么 | 判据来源 |
|---|---|---|
| **隔离（isolation）** | 断电域输出被钳到设计值了吗？ | 接收侧期望值（不是断电侧自己说的） |
| **保持（retention）** | 该保持的状态，唤醒后还在吗？ | 规格里标了必须保持的清单 |
| **电平转换** | 跨电压域的电平对不对？ | 域间电压关系 |

### 第 4 步：验「断得干不干净」

断电之后，**所有跨域输出必须是确定值**，不能是 X，不能是上一个值的残留：

- 在断电态下采样接收侧输入 → 必须是隔离钳位值
- 检查有没有「漏网信号」：该隔离的没隔离，X 传播到下游
- 仿真里 X 默认不报错，**要主动配置检查**（X-propagation 检查、断言 `!isunknown`）

### 第 5 步：验「醒得对不对」

唤醒不是「电回来了」就完，要验**恢复后的功能**：

| 检查项 | 说明 |
|---|---|
| 保持值恢复 | 保持寄存器 / 保持状态机的值 == 断电前 |
| 复位序列 | 重新上电的复位序列与首次上电一致 |
| 功能连续 | 唤醒后接着断电前的任务继续，结果正确 |
| 唤醒源 | 合法的唤醒源能唤醒，非法的不能 |

### 第 6 步：配电源状态覆盖率

把第 1 步的状态表落成覆盖点，**每个电源状态、每条合法转移都要被覆盖**（覆盖率建模法见
`verify/07_度量与报告/覆盖率模型/`）：

| 覆盖点 | 内容 |
|---|---|
| 域状态 | 每域每个状态各一个 bin |
| 状态转移 | 合法转移各一个 bin（多周期序列） |
| 状态组合 | 多域同时的状态组合（合法的） |
| 非法状态 | 定义为 illegal / forbidden bin，验证无法进入 |
| 唤醒源 | 每个唤醒源各一个 bin |

## 检查清单

| 检查项 | 问题 |
|---|---|
| 状态表 | 电源状态表列全了吗？非法组合定义了吗？ |
| 隔离值 | 钳位值由**接收侧**决定，在验证里核对了吗？ |
| 隔离时机 | 隔离信号在断电域断电**前**就有效吗？验过吗？ |
| 断电干净 | 断电态下所有跨域输出是确定值，没有 X 传播吗？ |
| X 检查 | 仿真真的开了 X 传播 / unknown 检查吗？（默认不开） |
| 保持 | 每个「必须保持」的状态都验过唤醒后的值吗？ |
| 唤醒 | 唤醒后功能连续性、复位序列都验了吗？ |
| 覆盖率 | 电源状态 / 转移 / 组合 / 唤醒源都进覆盖模型了吗？ |
| UPF↔RTL | UPF 声明的每个单元 / 端口，RTL 里都真的存在吗？ |

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 以为「仿真不报错 = 断电没问题」 | 仿真安静看起来就是对的 | 仿真默认不检查 X；断电域输出漂移被静默读成有效数据，硅上必错 |
| UPF 与 RTL 不一致 | 先写 UPF 或先写 RTL，两边各自演进 | 仿真报错，或更坏：**静默不生效**（隔离写了但 RTL 没那个控制信号） |
| 隔离控制信号自己也断了 | 「控制信号当然是本域的」 | 断电后隔离失效，等于没加 —— 而验证若只看「有没有报错」还会判过 |
| 只验「关」不验「醒」 | 断电动作直观、好写激励 | 唤醒后状态错 / 功能断，回归全过，硅上会现场翻车 |
| 电源切换用随机激励 | 想省事，交给约束随机 | 电源切换是多周期带控制的行为，随机撒不到；覆盖率永远 0% |
| 覆盖率只测域状态、不测转移 | 列状态最简单 | 状态到得了，但「怎么从 A 到 B」的非法 / 边界转移没验 |
| 唤醒源只验一个 | 有一个能醒就算通了 | 其余唤醒源路径没验，现场某个唤醒失效 |
| 把低功耗验证当纯 UPF 仿真 | 「上了 UPF 工具就自动验了」 | 工具提供状态建模，**激励和判据还得人写**，工具不替你判对错 |

> **最值钱的两条**：**X 检查**和**UPF↔RTL 一致性**。
> 前者是你的「断得干不干净」能不能被发现的唯一前提；后者是低功耗仿真头号崩点。

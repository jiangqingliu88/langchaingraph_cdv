# 约束·种子·覆盖率闭环

> **一句话**：**约束决定激励空间，种子决定探索路径，覆盖率决定下一步往哪走。**
> 三者是一个闭环，不是三件独立的事。

## 一、定义

```text
约束 ──生成──→ 激励 ──驱动──→ DUT
                  │              │
                  │              ↓
                  │         覆盖率采样
                  │              │
                  ↓              ↓
              种子筛选 ←── 覆盖率缺口分析
                  │              │
                  │              ↓
                  └──────→ 约束调整
```

| 要素 | 回答的问题 | 输出 |
|---|---|---|
| **约束** | 激励空间**有多大**？ | 合法的激励集合 |
| **种子** | 探索路径**怎么走**？ | 具体的激励序列 |
| **覆盖率** | 空间**探索到了吗**？ | 缺口清单和收敛状态 |

**闭环的运转**：每跑一批 → 看覆盖率 → 分析缺口 → 调约束 / 补定向 / 筛种子 → 再跑。

## 二、边界（不是什么）

| 它**不是** | 为什么容易这么以为 |
|---|---|
| 不是三个独立的阶段 | 时序上它们确实一前一后，看起来像流水线上的三道工序 |
| 不是"先写约束、再跑种子、最后看覆盖率"的单向流程 | 那是**开环**，跑完才知道结果，然后没有然后 |
| 不是工具流程 | 这是一种工作方式；工具（`urg`/`vcover`/仿真器）只是执行手段 |
| 不是只在回归末尾做的事 | 覆盖率在**第 2 批**就开始决定第 3 批跑什么了 |

**"看起来像流水线"是这个概念最容易被误解的地方。** 三者在时间上确实有先后，
但**后一步的结论会回头改前一步的输入** —— 缺了这条回头路，
前两步做得再规范也只是在扩大一个没人看的数字。

## 三、与易混概念的区别

### 与「覆盖率驱动验证（CDV）」的区别

| | CDV | 本卡 |
|---|---|---|
| 讲什么 | 覆盖率是**驱动**不是度量 | 三者**互相耦合**成一个环 |
| 方向 | 覆盖率 **→** 激励（一个方向） | 三个方向都算，且要形成回路 |
| 典型问题 | 「这个 bin 要怎么才能命中？」 | 「为什么这三件事必须一起做？」 |

CDV 是本闭环里**其中一个方向**（覆盖率 → 约束/激励）的深化，
见 `verify/02_验证方法学/覆盖率驱动验证/覆盖率驱动验证.md`。
本卡是三者的位置图，**不含各自的做法**。

### 与「回归」的区别

回归是**执行**：跑哪些用例、跑多少种子、结果怎么合并。
闭环是**决策**：下一轮跑什么、改哪个约束、加不加种子。
回归把闭环的决策执行出来，但回归本身不做决策。

### 与「覆盖率报告」的区别

报告回答"现在多少"。闭环要求的是**从这个数字往回走**：
哪个 bin 没命中 → 归到哪一类 → 该动约束还是加种子还是走豁免。
一个只报数字、不导向动作的覆盖率报告，对这个闭环没有价值。

## 四、闭环断在哪，就退化成什么样

**这是判断一个验证流程有没有真正在跑闭环的最快方法 —— 找断点。**

| 断在哪 | 退化成的样子 |
|---|---|
| 覆盖率不导向动作 | 覆盖率变成"汇报进度"的装饰，缺口没人认领 |
| 缺口不归因 | 所有缺口一律"再加点随机"，包括那些架构不可达的 |
| 约束没有 `targets` | 改了约束不知道影响谁，覆盖率变化无法归因 |
| 种子不筛选 | 回归时间被零贡献种子吃掉，且没有探索种子防过拟合 |
| 批次一次排满 | "覆盖率驱动"名存实亡，第 3 批打哪儿全靠猜 |
| 签核不看豁免比例 | 闭环的出口没人把守，`ignore_bins` 变成把数字凑到 100% 的快捷键 |

**每一行都对应一张卡**：这一列正是本知识库里「覆盖率」相关卡片存在的理由。

## 五、检查清单

| 检查项 | 问题 |
|---|---|
| 回头路 | 这一轮的覆盖率结论，真的改变了下一轮的约束或种子吗？ |
| 归因 | 缺口有归因吗？还是统一"再加随机"？ |
| 约束 | 每个约束能说清它服务于哪个 bin 吗？ |
| 种子 | 种子是筛出来的，还是随手定的？有探索种子吗？ |
| 批次 | 下一批的计划是这一批结束时定的吗？ |
| 出口 | 签核时未覆盖 bin 的豁免比例有上限吗？ |

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 把它当成三个阶段 | 时间上确实分先后 | 开环：跑完看数字，然后没有然后 |
| 只在回归末尾看覆盖率 | 覆盖率本来就是"最后跑出来的" | 错过第 2→3 批那次关键的调整窗口 |
| 三者由不同的人各自管 | 分工明确、责任清晰 | 环断在交接处：改约束的人不知道种子策略，筛种子的人不知道缺口性质 |
| 用覆盖率数字汇报代替闭环 | 汇报需要一个数 | 数字越来越漂亮，缺口一个没少 |
| 以为买了工具就有了闭环 | 工具都有覆盖率功能 | 工具给数字，闭环要靠人走那几步回头路 |

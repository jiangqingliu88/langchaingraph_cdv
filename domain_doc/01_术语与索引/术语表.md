# 术语表

**一句话定义 + 展开在哪张卡。** 这里不写完整定义 —— 完整定义写在对应的卡里，
两处都写完整定义就等于同一个定义有两份。

| 术语 | 英文 | 一句话 | 展开 |
|---|---|---|---|
| 验证 | Verification | 证明设计**符合规格**（做对了产品） | 待补 |
| 测试 | Test | 证明制造出来的芯片**没有物理缺陷**（产品做对了） | 待补 |
| DUT | Design Under Test | 被验证的设计本体 | 待补 |
| TB | Testbench | 给 DUT 施加激励并检查响应的那一套 | 待补 |
| UVM | Universal Verification Methodology | 一套组件化 + 分层 + 可复用的验证方法学与类库 | [验证方法学](../verify/02_验证方法学/_index.md) |
| 覆盖率驱动验证 | CDV, Coverage-Driven Verification | 从覆盖目标反推该造什么激励 | [覆盖率驱动验证](../verify/02_验证方法学/覆盖率驱动验证/) |
| 功能覆盖率 | Functional Coverage | 由验证者**定义**的「哪些场景测到了」 | [覆盖率模型](../verify/07_度量与报告/覆盖率模型/) |
| 代码覆盖率 | Code Coverage | 由工具**自动统计**的「哪些代码被执行了」 | [覆盖率模型](../verify/07_度量与报告/覆盖率模型/) |
| 签核 | Sign-off | 有证据地宣布「**某一个阶段的活干完了**」—— 设计与验证各有一道门 | [流程与签核](../02_流程与签核/_index.md) |
| RTL Freeze | RTL Freeze | 设计侧的出档门：RTL 基线冻结，此后改动走 ECO | [RTL Freeze](../02_流程与签核/RTL_Freeze.md) |
| 反模式 | Anti-pattern | 看起来合理、实际会吃亏的做法 | [04_治理运营/卡片模板.md](../04_治理运营/卡片模板.md) |

> 上表只是**骨架**。往里加词的时候，顺手把「展开」那一格填上 ——
> 空着的话，这个词迟早会有第二个人再定义一次。

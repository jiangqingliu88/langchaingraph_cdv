## 为什么分两翼，而不是一堆平铺的域

| 理由 | 说明 |
|---|---|
| 找人 | 设计工程师不用穿过「验证方法学」「协议与VIP」才能找到「综合与时序」 |
| 防重复 | 术语表、治理文档、标准合规**只存一份**。两棵树各存一份，就是两份会漂移的真相 |
| 边界可判 | 一张卡归哪翼，看它回答 **「RTL 该怎么写」** 还是 **「怎么证明 RTL 对」** |

**判据宁可判错也不要判模糊。** 一个知识点在两翼各有一份，比放错翼坏得多 ——
放错翼是找得慢，两份是「改了一处，另一处变成错的，而没人会发现」。

## 一条铁律：一个知识点只有一个家

每条知识落在**一个**域里，其它域只能**链接**它，不能复制它。

理由和这个仓库对工具链的要求是同一条：**两份就会漂移，而漂移了你不知道哪份是真的。**

这条在两翼结构下比原来更要紧：CDC 就是最容易踩的例子 ——

| CDC 的哪一面 | 该去哪 |
|---|---|
| 同步器怎么设计、亚稳态怎么处理、RDC 复位怎么隔离 | `design/04_DFT_CDC_安全/` |
| CDC 怎么验、要打断言还是做形式、SpyGlass 报错怎么读 | `verify/02_验证方法学/` 或 `verify/04_工具与脚本/` |

**一张卡只回答一个问题**，所以这是两张卡，互相链接，不互相抄。

所以每个域的 `_index.md` 都写了「**不放什么**」，那一条比「放什么」更重要：
**一个知识库烂掉，几乎总是从「什么都往里塞」开始的。**

## 与仓库里其它文档的关系

本知识库放**领域方法论**（设计与验证这件事本身怎么做），不放**本仓库怎么用**：

| 内容 | 在哪 |
|---|---|
| 某个工具（case 建模 / ISA 激励 / UVM 生成）怎么跑 | 各工具自己的 `readme.md` |
| CLI 与工作台怎么用 | 仓库根的 `README.md`、`CLAUDE.md` |
| **设计 / 验证这件事本身怎么做** | **本知识库** |
| 零散笔记、草稿、参考资料 | `doc/`（不是本库 —— 见下） |

> `doc/` 与本库是**两种东西**：`doc/` 是笔记堆，本库是**有结构、有治理**的知识库。
> 从 `doc/` 往本库搬的时候，要按卡片模板重写一遍 —— 直接搬文件等于把笔记堆换个地方堆。

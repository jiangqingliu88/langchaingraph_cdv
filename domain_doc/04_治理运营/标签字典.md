# 标签字典

**受控词表**：写卡时从下面挑，不在表里的先讨论再补。

不这么做的话，同一件事会有四种写法（`AXI` / `axi` / `AXI4` / `amba-axi`），
检索时谁都搜不全 —— 而以「可检索」为卖点的库，搜不全就等于没有。

## 维度

一张卡每维**取 0 或 1 个**（`tags` 里放值），除非确实跨维。

| 维度 | 取值 |
|---|---|
| **领域** | `IC设计` `IC验证` |
| **阶段** | **设计侧**：`需求` `微架构` `RTL编码` `综合` `时序收敛` `DFT` `RTL Freeze`<br>**验证侧**：`计划` `TB架构` `编码` `调试` `回归` `覆盖率` `签核` `后仿` |
| **层级** | `模块` `子系统` `SoC` `门级` `芯片` |
| **技术** | `CRV` `定向` `形式` `断言` `覆盖率` `低功耗` `安全` `Emulation` `原型`<br>**设计侧**：`综合` `时序` `PPA` `DFT` `CDC` `RDC` |
| **方法学** | `UVM` `OVM` `VMM` `eRM` `ABV` `CDV` `UPF` `ISO26262` |
| **工具** | **验证侧**：`VCS` `Xcelium` `Questa` `Verdi` `JasperGold` `VCFormal` `SpyGlass`<br>**设计侧**：`DC` `Genus` `PrimeTime` `Formality` `Conformal` `Tessent` |
| **语言** | `SystemVerilog` `Verilog` `VHDL` `SystemC` `C++` `Python` `Tcl` |
| **协议** | `AXI` `AHB` `APB` `CHI` `PCIe` `CXL` `USB` `DDR` `Ethernet` `MIPI` `UCIe`<br>`SPI` `I2C` `UART` `JTAG` |
| **角色** | `设计工程师` `DV工程师` `架构师` `经理` `形式` `低功耗` `DFT工程师` `Emulation` |
| **质量** | `草稿` `评审中` `已验证` `过期` |
| **来源** | `标准` `论文` `项目` `厂商` `社区` |
| **复用** | `通用` `项目` `团队` |
| **知识库** | 基础设施文档用（**知识卡不用这一维**）：`知识库` `治理` `模板` `标签` `流程` `术语` `索引` `架构` |

> **受控词表管的是知识卡。** 根文档、域索引、治理文档、术语/索引文档是**基础设施**，
> 不是卡，它们的 `tags` 走「知识库」那一维，不受卡片契约约束（见 `卡片模板.md`）。

> `编码` 在验证侧指 Testbench / 用例编码，与设计侧的 `RTL编码` 区分开。
> 一张卡跨两翼时（典型是 CDC：设计侧怎么处理 vs 验证侧怎么打断言），
> **按「这张卡回答哪个问题」选阶段**，不要两边都打 —— 两边都打的卡，检索时两边都排后面。

> `质量` 与 frontmatter 的 `status` 是**同一件事**。放在字典里是为了让「按状态筛」
> 走同一条路，不用两套。**写入时以 `status` 为准，`tags` 里可不重复。**

## 关系的取值（`related` 用）

`属于` `依赖` `替代` `对比` `应用于` `由工具支持` `被协议约束` `案例验证` `角色使用` `指标衡量`

前四个是结构性的（构成知识图谱的边），后六个是导航性的。

## 加新标签

先在 [`索引.csv`](../01_术语与索引/索引.csv) 里搜一遍同义项 —— 九成情况下你要的标签
已经存在，只是名字不同。确实要加时，**一次加成对**：`标签` + 一句「它和 X 差在哪」。

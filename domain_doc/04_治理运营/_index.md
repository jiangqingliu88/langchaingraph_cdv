# 治理运营

**位置**：共用域

> 知识库**自己怎么运转**：卡片模板、标签字典、贡献与评审流程、版本规范。

| 文件 | 管什么 |
|---|---|
| [卡片模板.md](卡片模板.md) | 十种卡的结构 + 共用的 frontmatter（**字段是契约**） |
| [标签字典.md](标签字典.md) | 受控词表 —— 标签从表里挑，不自造 |
| [贡献指南.md](贡献指南.md) | 加一条知识的完整动作 |
| [评审流程.md](评审流程.md) | 草稿 → 评审中 → 已验证 → 过期 的状态机 |
| [版本规范.md](版本规范.md) | 条目级版本、过期标记、id 不复用 |

## 边界

**不放**：知识本身。这里放的是「怎么写知识」。

## 为什么要有这一层

没有治理的知识库都会走到同一个结局：**半年后没人敢改，因为不知道改了会影响谁；一年后没人敢用，
因为不知道哪条还是对的。** 五份文件对应的是五个具体的失效点：

- 没有模板 → 每张卡结构不同，检索脚本没法读
- 没有受控标签 → 同义标签并存，搜不全
- 没有评审状态 → 草稿与已验证混在一起，读者无法判断可信度
- 没有版本 → 「这条过时了没有」没法回答
- 没有过期流程 → 要么留着错的，要么一删了之（把「以前为什么这么做」也删了）

# 版本规范

**条目级版本**，不是库级。每条卡自己写着 `version` 与 `updated` —— 知识库的更新
是零散的，用一个全局版本号只会让「这条卡过时了没有」没法回答。

## 什么时候升

| 改动 | 版本 |
|---|---|
| 措辞、错别字、格式 | 不升（改 `updated` 即可） |
| 补一段、纠一处**事实**、加一个坑 | 升 minor（`1.0` → `1.1`） |
| 结论变了（原来是这么做的，现在不这么做了） | 升 major（`1.1` → `2.0`），并在卡顶写一句「**v2 改了什么、为什么**」 |

## 过期怎么标

**不删卡**，标 `status: 过期`，并在开头写清：

```markdown
> ⚠️ **已过期**（2026-10-12）：<哪条依据变了>。
> 现在应当看 [<替代卡的 id>]。
```

保留而不删的理由：**「以前为什么这么做」本身就是一种知识**。删掉之后，
遇到旧项目的人会重新踩一遍，而且没人知道这个坑踩过。

## `id` 不复用

`id` 一旦分配就不再改、也不回收 —— 别的卡的 `related` / `prerequisites` 指着它。
删卡时把 `id` 标为 retired，不要给新卡用。

## 与 git 的关系

`updated` 是**知识更新**的时间，`git log` 是**文件变更**的时间。两者不是一回事：
格式化一次会动后者不动前者。**判断一条知识新不新，看 `updated`。**

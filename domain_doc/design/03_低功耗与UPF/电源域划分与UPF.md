# 电源域划分与 UPF 落地

> **一句话**：低功耗设计的三件事 —— **切域、隔离、保持** ——
> 每一件都对应一个「不写就会在断电时出问题」的具体后果。UPF 只是把这三件事写成命令。

## 适用场景

- 新模块要做低功耗，需要决定电源域怎么切
- UPF 已经有了，但**仿真行为与综合行为对不上**
- 断电后唤醒，寄存器值没了 / 输出漂了

## 不适用

| 你实际想干的事 | 该去哪 |
|---|---|
| 验证电源状态覆盖到了没有 | `verify/02_验证方法学/低功耗_安全_车规/` |
| 想知道功耗省了多少 | `../02_综合_时序_PPA/` |
| 只是加了时钟门控 | 那不需要 UPF，见下文「什么时候用不上 UPF」 |

## 步骤

### 第 1 步：切电源域

**判据不是「哪里想省电」，是「哪里可以同时断电」**：

| 判据 | 说明 |
|---|---|
| 同时在用 | 同一个域里的模块，必须能接受「同时上电、同时断电」 |
| 边界可隔离 | 跨域的每条信号都能被隔离 —— 划不出干净边界的域，不要切 |
| 状态可重建 | 断电后必须能恢复的状态，要么放保持寄存器，要么放不掉电的域 |

**切错了的表现**：域切完发现两个模块「大部分时候一起用，偶尔分开」——
这种域带来的隔离逻辑成本超过省下的电。

### 第 2 步：隔离（isolation）—— 什么时候必须加

**只要一条信号从「可能断电的域」连到「一直开着的域」，就必须隔离。**

不隔离的后果很具体：断电域的输出**漂到一个不确定的电平**，
接收侧当成有效数据读进去 —— 这不是「可能出错」，是必然出错，且仿真时看不出来
（仿真里断电域的线是 X，RTL 仿真默认不检查）。

| 隔离位置 | 加在哪一侧 |
|---|---|
| 输出信号 | 断电域的输出侧，或接收域的输入侧（二选一，别两边都加） |
| 隔离时钳到什么值 | **由接收侧决定** —— 接收侧希望看到 0 还是 1，不是断电侧说了算 |
| 隔离信号谁来控 | 必须在**断电域还活着的时候**就有效 |

### 第 3 步：保持（retention）—— 什么时候必须加

**断电后必须记住的状态**才用保持寄存器。判据：

- 配置寄存器（掉电重启后仍要生效的）→ **放到不掉电的域**，比用保持寄存器便宜
- 状态机的状态 → 通常**不需要保持**，重启本来就是设计的一部分
- 真需要保持的极少 —— **默认不保持**，逐条论证

**为什么默认不保持**：保持寄存器要额外的控制信号与备份电源，
加多了会把省下的功耗吃掉，还把时序搞复杂。

### 第 4 步：落成 UPF

三件事在 UPF 里一一对应：

| 设计概念 | UPF 命令 | 容易漏的点 |
|---|---|---|
| 电源域 | `create_power_domain` | 域内元素要显式归属，别靠默认 |
| 隔离 | `set_isolation` | 要配 `set_isolation_control`，否则谁控制它没定义 |
| 保持 | `set_retention` | 要配 `set_retention_control`，同理 |
| 电源状态 | `add_port_state` / `create_pst` / `add_pst_state` | 状态表不全 → 仿真无法判断非法状态 |
| 电平转换 | `set_level_shifter` | 仅当**电压不同**才需要；同压不同域不需要 |

**UPF 与 RTL 的一致性**：UPF 里声明的东西必须在 RTL 里真的存在
（隔离单元、保持寄存器的控制端口）。这是**最常见的崩点** ——
UPF 写了 `set_isolation`，RTL 里根本没有那个控制信号，仿真直接报错或静默不生效。

## 什么时候用不上 UPF

只有**时钟门控**、没有电源域切换的设计，不需要 UPF。
把时钟门控也写进 UPF 是常见的过度设计 —— UPF 管的是**电源**，不是时钟。

## 检查清单

| 检查项 | 问题 |
|---|---|
| 域边界 | 每条跨域信号都考虑过隔离了吗？ |
| 隔离值 | 钳位的值是由**接收侧**决定的吗？ |
| 隔离控制 | 控制信号在断电域断电时仍然有效吗？ |
| 保持 | 每个保持寄存器都论证过「为什么必须保持」吗？ |
| 电平转换 | 跨域是否有电压差？有差才要 shifter |
| 一致性 | UPF 声明的每个单元/端口，RTL 里都真的存在吗？ |
| 状态表 | 电源状态表覆盖所有合法组合了吗？非法组合定义了吗？ |
| 复位 | 断电域重新上电后，复位序列与首次上电一致吗？ |

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 跨域不隔离 | 仿真不报错（X 不检查） | 硅上断电域输出漂移，接收侧读到垃圾 |
| 隔离控制信号自己也断了 | 「控制信号当然是本域的」 | 断电后隔离失效，等于没加 |
| UPF 与 RTL 不一致 | 先写 UPF 后写 RTL，或反过来 | 仿真报错，或更坏：静默不生效 |
| 保持寄存器加太多 | 「加了更保险」 | 省下的电被吃掉，时序更复杂 |
| 同压也加 level shifter | 看起来更「规范」 | 白增面积与延迟 |
| 把时钟门控塞进 UPF | 「都是低功耗」 | UPF 管电源不管时钟，混淆后两边都难维护 |

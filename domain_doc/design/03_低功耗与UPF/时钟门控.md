# 时钟门控：什么时候加、加在哪

> **一句话**：门控省的是**动态功耗**（时钟树翻转），断电省的是**静态功耗**（漏电）——
> **两件不同的事，用两套机制。** 门控只需要一个 ICG 单元，**不需要 UPF**。

## 适用场景

- 模块里有大量寄存器，但同一时刻只有一部分在被写
- 想省时钟树翻转功耗（大块寄存器 + 高频时钟，是最大头）
- 审查一段门控逻辑：它有没有毛刺、用的对不对

## 与电源域的区别（最常被混淆）

| 维度 | 时钟门控（本卡） | 电源域（KB-DV-PWR-001） |
|---|---|---|
| 省什么功耗 | **动态**（翻转） | **静态**（漏电）+ 部分动态 |
| 状态是否保留 | **保留**（寄存器值不变） | **丢失**（除非保持寄存器） |
| 需要 UPF 吗 | **不需要** | 需要 |
| 需要隔离吗 | **不需要** | 需要 |
| 实现单元 | 一个 ICG（集成时钟门控单元） | 隔离/保持/开关单元 |
| 恢复代价 | 下一个时钟沿即恢复 | 需要上电、复位、重新配置 |

**判据**：问「关掉之后，这块逻辑的寄存器值还要不要」。
要保留 → 门控；可以丢 → 才可能是电源域。

## 步骤

### 第 1 步：选粒度

| 粒度 | 加在哪 | 取舍 |
|---|---|---|
| **细粒度**（每寄存器组一个门） | 每个功能块独立门控 | 省得多，但 ICG 数量多、面积大、门控使能的组合逻辑可能成为新关键路径 |
| **中粒度**（每功能块一个门） | 模块级使能 | 最常用 —— 面积与收益平衡 |
| **粗粒度**（每子模块一个门） | 大模块级 | 省 ICG，但模块里哪怕一个寄存器要写，整块时钟就得开着 |

**经验判据**：门控的**使能信号**必须比被门控的时钟**早稳定**（且不依赖被门控的逻辑），
否则使能本身的组合逻辑会成为新的时序关键路径。

### 第 2 步：用 ICG 单元，不要手写与门

**这是本卡最重要的一条。**

手写与门（`gated_clk = clk & enable`）的问题：`enable` 可能在时钟高电平期间变化
→ 输出产生**毛刺**（窄脉冲），触发下游触发器误翻转，或违反时钟的窄脉冲约束。

**ICG（集成时钟门控单元）的正确行为**：在**时钟低电平期间锁存** `enable`，
高电平期间用这个锁存值门控时钟 —— 使能窗口被对齐到时钟低电平，输出无毛刺。

| 做法 | 结果 |
|---|---|
| `assign gated_clk = clk & enable;` | 有毛刺，**错** |
| 手动加 latch 再与门 | 容易做错（latch 透明窗口设反），且综合/DFT 不可识别 |
| 用工艺库 ICG 单元（`CKLNQD` / `CLKGATETST` 之类） | 正确，综合与 DFT 都能识别 |

**为什么必须用库单元**：只有标准 ICG 单元才能被 DFT 工具识别并在测试模式下**旁路**
（强制时钟常开，见 KB-DV-DFT-002）。手工门控无法被旁路，会导致扫描测试时钟不可控。

### 第 3 步：设计使能逻辑

- **使能信号必须来自同域寄存器**（保证它相对时钟有确定的时序）
- **使能逻辑不能依赖被门控逻辑自己**（否则门控后自己无法把自己打开，形成死锁）
- 使能在时钟高电平期间**必须稳定**（由第 2 步的 ICG 保证，但源信号本身也要满足）
- **复位附近要小心**：复位释放后使能若未初始化，可能造成首拍时钟没开

### 第 4 步：标注对下游的影响

| 下游 | 门控带来的影响 | 要做的事 |
|---|---|---|
| **综合** | ICG 引入时钟树延迟，需在 SDC 里体现 | 见 `../02_综合_时序_PPA/SDC约束.md`（KB-DV-SYN-002）的时钟定义 |
| **DFT** | 测试模式必须让 ICG 旁路（时钟常开） | 每个 ICG 要有测试使能控制，见 KB-DV-DFT-002 |
| **验证** | 门控使能也是一种「状态」，要验它开/关的行为 | 验证侧覆盖点（低功耗验证域） |
| **CDC** | 门控时钟是**生成时钟**，跨域时按生成时钟处理 | SDC 要 `create_generated_clock` |

## 检查清单

| 检查项 | 问题 |
|---|---|
| 类型 | 这块想省的是动态还是静态功耗？选对机制了吗？ |
| 单元 | 用的是库 ICG 单元，还是手写与门？ |
| 使能来源 | 使能来自同域寄存器吗？会不会依赖被门控逻辑？ |
| 优先级 | 门控使能的组合逻辑有没有成为新的关键路径？ |
| 复位 | 复位释放后首拍时钟会不会没开？ |
| DFT | 每个 ICG 都有测试旁路控制吗？ |
| SDC | 门控时钟在约束里是 `create_generated_clock` 吗？ |
| 验证 | 门控开/关两种状态都验到了吗？ |

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 手写 `clk & enable` | 少一个单元，代码直观 | 毛刺进下游触发器；DFT 无法旁路，扫描测试坏 |
| 把门控写进 UPF | 「都是低功耗」 | UPF 管电源不管时钟，混淆后两边都难维护（同 KB-DV-PWR-001 的坑） |
| 门控使能依赖被门控逻辑 | 「逻辑上正好需要」 | 门控后无法自解，死锁 |
| 细粒度门控满地加 | 「多关多省」 | ICG 面积与使能逻辑的组合延迟吃掉了省的电，时序更差 |
| 门控忘了测试旁路 | 「功能模式没问题」 | 测试模式下时钟被关死，scan 链不翻转，DRC 报错 |
| 使能在高电平期间变化 | 只看功能、没看时序窗口 | 即使有 ICG，源信号违规仍会造成亚稳/毛刺 |
| 门控时钟不写 `create_generated_clock` | 「就是同一个时钟」 | 时序分析按源时钟走，门控后路径的时序不正确 |

> **一句话记忆**：**门控改的是「时钟有没有在跳」，电源域改的是「电有没有在」**。
> 前者寄存器值还在，后者没了 —— 这条区分开，两种机制就不会用混。

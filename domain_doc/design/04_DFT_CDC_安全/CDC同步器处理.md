# CDC：设计侧同步器处理

> **一句话**：跨时钟域的问题不是「时序不够快」，是**亚稳态**——
> 一个信号在两个时钟边沿附近变化时，接收侧触发器可能进入既不是 0 也不是 1 的中间态。
> 同步器做的就是「给它时间稳定下来」。**这类问题仿真几乎抓不到**，所以只能靠设计侧做对。

**这是设计翼的 CDC 卡。** 验证侧怎么检查它，是另一张卡（`verify/` 各域），不在这里重复。

## 适用场景

- 设计里存在两个以上时钟域，或两个以上复位域（RDC 同样是 CDC 问题）
- CDC 工具报了一批违例，需要判断哪些是真问题

## 四类信号，四种做法

**先分类，再动手。** 用错同步器和不加同步器一样危险。

### 1. 单比特电平（最常用）

**两级触发器**（`2-FF synchronizer`）：

```systemverilog
// 目的时钟域
logic [1:0] sync_ff;
always_ff @(posedge dst_clk or negedge rst_n)
  if (!rst_n) sync_ff <= 2'b00;
  else        sync_ff <= {sync_ff[0], src_level};
// 用 sync_ff[1]
```

**两个必须注意的点**：

- **源信号必须由源时钟域的寄存器驱动**（不能是组合逻辑输出）——
  组合输出会有毛刺，而毛刺可能正好落在采样窗口
- **两级只够「降低」亚稳态概率，不是消除**。MTBF 要求高时算一下，可能要三级

### 2. 单比特脉冲

**两级触发器不够** —— 脉冲可能比目的时钟周期还窄，直接漏掉。

| 做法 | 适用 |
|---|---|
| 先展宽（源域把脉冲拉成足够宽的电平）再同步 | 简单、可靠，代价是延迟 |
| 用握手（源域发请求，目的域回确认） | 需要确认收到时 |
| 用异步 FIFO | 脉冲很密时 |

### 3. 多比特（总线 / 计数器）

**逐位同步是错的** —— 各位到达时间不同，接收侧会读到**介于新旧值之间的非法组合**。

| 做法 | 适用 |
|---|---|
| 格雷码 | 计数器类，相邻值只变一位 |
| 握手 | 通用，代价是吞吐 |
| 异步 FIFO | 高吞吐数据流 |
| 保持到稳定后再采（源侧先保证数据稳定，再同步一个「有效」标志） | 数据变化不频繁 |

**判据**：多比特**要么只变一位**（格雷码），**要么整组原子交付**（握手 / FIFO）。
没有第三条路。

### 4. 复位（RDC）

- **异步复位、同步释放**：复位断言可以异步（快），释放必须同步（否则各触发器释放时刻不同）
- 复位域之间同样要同步，规则与时钟域相同
- 复位同步器本身**不能被复位**（否则死锁）—— 这条最容易被漏

## 加完同步器之后：路径该怎么约束

**这一步最容易搞错。** 同步器的**第一级触发器**仍然是跨域路径，
它**必须**被时序分析以某种方式处理 —— 但方式是「允许它可能失败」，不是「假装它不存在」：

| 路径 | 约束 |
|---|---|
| 源寄存器 → 同步器第一级 | `set_false_path` 或 `set_max_delay -datapath_only`（推荐后者：它仍然约束数据路径延迟，避免布线过长） |
| 同步器第一级 → 第二级 | **正常时序约束**，不能设 false path（这两级在同域内） |
| 同步器输出 → 目的域逻辑 | 正常时序 |

**为什么推荐 `set_max_delay -datapath_only`**：纯粹的 `set_false_path` 会让工具完全不管这条路径，
布线可能绕很远；`datapath_only` 保留数据路径延迟约束，只放宽时钟关系。

## 检查清单

| 检查项 | 问题 |
|---|---|
| 分类 | 每个跨域信号都归到四类之一了吗？ |
| 源侧 | 跨域信号的源是**寄存器输出**吗（不是组合逻辑）？ |
| 单比特 | 两级够吗？MTBF 算过吗？ |
| 脉冲 | 宽度够被采到吗？还是要展宽/握手？ |
| 多比特 | 是格雷码或握手/FIFO 吗？（逐位同步是大忌） |
| 复位 | 复位释放同步了吗？复位同步器自己被复位了吗？ |
| 约束 | 同步器第一级前的路径约束了吗？第一级到第二级**没**被误设 false path 吧？ |
| 时钟组 | 异步时钟组设了 `set_clock_groups -asynchronous` 吗？ |

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 多比特逐位同步 | 每位的两级触发器写法一样，看着对称 | 读到非法中间值，且**概率性出现**，最难查 |
| 用组合逻辑驱动同步器 | 少一级寄存器 | 毛刺进采样窗口，亚稳态概率飙升 |
| 同步器第一级到第二级也设 false path | 「都是跨域路径，一起设了」 | 两级之间失去时序保证，同步器失效 |
| 复位同步器被自己复位 | 「复位信号当然要接复位」 | 复位释放同步器自身不动，可能死锁 |
| 只加两级不算 MTBF | 「两级是行业惯例」 | 高频/低 MTBF 要求下不够，概率性失效 |
| 仿真没报错就以为没问题 | 亚稳态在 RTL 仿真里**根本不建模** | 硅上才暴露，且难复现 |

> **最后一条是本卡存在的理由**：CDC 问题**在 RTL 仿真里看不见**。
> 所以「验证通过了」对 CDC 不构成任何证据 —— 这只能靠设计侧做对，
> 外加验证侧的专门检查（CDC 工具、断言、形式）。

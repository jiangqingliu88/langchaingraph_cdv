# 扫描链与 DFT 插入

> **一句话**：DFT 的目标是「让芯片内部状态**可观测、可控制**」——
> 把一堆触发器串成移位链，测试模式下能把任意状态移进去、把结果移出来。
> 它改变的是**时钟与复位的控制权**，所以必须在设计侧就把控制通路留出来。

## 适用场景

- 设计进入 DFT 阶段，规划扫描链的条数、长度、连接顺序
- 测试模式下时钟/复位不可控，或 ATPG DRC 报错
- 要给出「测试模式需要哪些时序例外」

## 不适用

| 你实际想干的事 | 该去哪 |
|---|---|
| 功能模式下跨时钟域信号怎么同步 | `CDC同步器处理.md`（KB-DV-DFT-001） |
| 故障覆盖率 / ATPG 怎么跑 | 工具域 / 测试相关卡 |
| 时序例外的通用写法 | `../02_综合_时序_PPA/SDC约束.md`（KB-DV-SYN-002） |
| 时钟门控本身怎么加 | `../03_低功耗与UPF/时钟门控.md`（KB-DV-PWR-002） |

## 步骤

### 第 1 步：扫描链组织

**扫描链 = 把测试模式下的触发器接成一条移位寄存器链**。

| 参数 | 取舍 |
|---|---|
| **链条数** | 条数多 → 每条短，移位周期少（测试时间短），但要更多测试端口/引脚 |
| **链长** | 链长要**尽量均匀** —— 最长的那条决定测试时间，长短悬殊会浪费 |
| **连接顺序** | 同域、相邻的触发器连一起，减少跨域走线（也便于物理布局） |
| **链内不含的** | 时钟产生逻辑、锁存器、ICG 使能寄存器（见第 3 步的特殊处理） |

**判据**：链条数与引脚数、测试时间三者互相制约，**先定测试时间预算，再倒推链条数**。

### 第 2 步：测试模式下的时钟与复位

**核心问题：功能模式下时钟由功能逻辑产生，测试模式下必须由测试端口直接控制。**

| 对象 | 功能模式 | 测试模式 | 怎么实现 |
|---|---|---|---|
| **时钟** | 来自 PLL / 分频 / 门控 | 来自**测试时钟端口**（ATE 直驱） | 时钟 MUX，用测试模式信号选择 |
| **复位** | 功能复位 | **释放并在测试期间保持不变** | 复位在测试模式下被旁路/强制无效 |
| **时钟门控单元** | 由功能使能控制 | **必须旁路，时钟常开** | ICG 的测试使能强制有效（见 KB-DV-PWR-002） |
| **异步复位** | 正常工作 | 测试期间不能动 | 强制无效，否则移位中途被复位清零 |

**为什么复位在测试模式要保持无效**：扫描移位的几十上百拍里，复位一旦有效，
链上的状态被清空，移进去的激励全丢。**这是 DFT DRC 最常见的一类报错。**

### 第 3 步：多时钟域扫描

| 情况 | 处理 |
|---|---|
| **多时钟域** | 每条链**只放同一个时钟域的触发器**（跨域触发器不能串在一条链里） |
| **慢时钟域** | 不能和快时钟域混链，否则移位受最慢时钟限制 |
| **时钟域间** | 移位时各域时钟**是否同时驱动**要明确（多数做法是分组移位） |
| **门控时钟域** | 测试模式旁路 ICG，让该域时钟常开 |

**判据**：问「这条链上的触发器，移位的那个时钟是同一个吗」。
不是 → 拆链。混域链会让移位在某个边沿漏掉一级，ATPG 出的 pattern 全错。

### 第 4 步：给测试模式写时序例外

测试模式下有多组互斥的时钟，功能模式的时序约束在这里**不适用**：

| 约束 | 用途 |
|---|---|
| `set_clock_groups -physically_exclusive` | 功能时钟与测试时钟**物理互斥**（MUX 只选一个） |
| `set_false_path` | 测试模式下不关心的功能路径 |
| 测试模式专用 SDC | 通常**单独一份**，与功能模式 SDC 分开，靠模式变量切换 |

**要点**：测试模式的例外**同样要有理由**（同 KB-DV-SYN-002 的原则）——
「这是测试时钟，功能模式下不生效」是理由；「先设了再说」不是。

### 第 5 步：跑 DFT DRC 并修正

在给后端之前，先跑 DFT 规则检查，把下面几类清掉：

| DRC 类别 | 含义 |
|---|---|
| 不可控时钟（uncontrollable clock） | 时钟在测试模式下无法被测试端口控制 |
| 不可控/不可观测（uncontrollable / unobservable） | 关键信号在测试模式下无法驱动或观测 |
| 链内混域 / 链长不匹配 | 见第 3 步与第 1 步 |
| 锁存器/黑盒阻挡 | 链被 latch 或未建模模块打断 |

## 检查清单

| 检查项 | 问题 |
|---|---|
| 链划分 | 每条链都是单时钟域吗？链长均匀吗？ |
| 测试时钟 | 测试时钟能直接控制所有域吗？MUX 加了吗？ |
| 复位 | 测试模式下复位强制无效了吗？ |
| ICG | 每个门控单元在测试模式下旁路（常开）了吗？ |
| 时钟产生 | PLL / 分频 / 门控的逻辑在测试模式下被旁路了吗？ |
| 例外 | 测试模式的时序例外单独成文件，且每条有理由吗？ |
| DRC | DFT DRC 干净了吗？ |
| 保持 | 移位时的保持时间（scan shift hold）查过了吗？ |

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 复位没有在测试模式旁路 | 「复位接上更安全」 | 移位中途被清零，移进去的 pattern 全丢，DRC 报错 |
| 跨时钟域触发器串进同一条链 | 「链短一点，走线方便」 | 移位时钟不一致，边沿漏掉一级，pattern 全错 |
| 忘了旁路 ICG | 只盯着功能逻辑 | 测试模式时钟被门控关死，部分链根本不翻转 |
| 把时钟产生逻辑也串进链 | 「所有触发器都该在链里」 | 时钟产生逻辑进了链，移位时改变时钟，形成循环 |
| 测试模式沿用功能 SDC | 不想多写一份约束 | 功能例外在测试模式不成立，产生大量假违例或漏检 |
| 链长悬殊 | 没规划，随手连 | 最长那条决定测试时间，测试成本被最差链吃掉 |
| 只给 RTL 不给 DFT 控制信号 | 「后端会加」 | DFT 逻辑无法插入，设计在 RTL 阶段不可测 |
| 不看 scan shift hold | 只查 shift setup | 移位时的保持违例，pattern 在硅上失效且难定位 |

> **要记住的一句**：**DFT 不是「后端加个链」，是设计侧必须预留的一整套测试控制通路**。
> 时钟、复位、门控、时钟产生逻辑 —— 每一处都要能被测试模式接管，
> 缺一处，整条链就可能测不了。

# 时序收敛：违例分类与处理顺序

> **一句话**：时序报告里**大部分违例不是「逻辑太慢」，是「约束写错了」或「路径根本不该存在」**。
> 先分类再动手 —— 直接改 RTL 是最后一步，不是第一步。

## 适用场景

- 综合跑完，WNS / TNS 为负，违例数量大到没法一条条看
- 改了几轮 RTL，违例没怎么少 —— 说明分类这步跳过了

## 不适用

| 你实际想干的事 | 该去哪 |
|---|---|
| 违例就三五条，原因清楚 | 直接改，不用本卡 |
| 还没综合，想先把 RTL 结构写对 | `../01_微架构与RTL编码/` |
| 是跨时钟域路径报违例 | `../04_DFT_CDC_安全/` —— 那多半是**不该被时序分析**的路径 |

## 步骤

### 第 1 步：先看两个数，确定问题规模

| 指标 | 含义 | 怎么用 |
|---|---|---|
| **WNS**（最差负裕量） | 最差那条路径差多少 | 决定**能不能收敛**：差 50ps 和差 2ns 是两件事 |
| **TNS**（总负裕量） | 所有违例路径的裕量之和 | 决定**值不值得收敛**：WNS 小但 TNS 大 = 一大批路径都差一点 |

**先看这两个数，再决定要不要往下走。** WNS 差一个数量级超过时钟周期，
说明这不是收敛问题，是结构问题 —— 该回上一域改微架构。

### 第 2 步：把违例分三类（这一步决定后面省几轮）

| 类别 | 特征 | 处理 |
|---|---|---|
| **① 约束写错** | 路径本不该被这样约束：异步跨域、假路径、多周期路径 | 改 SDC。**这类最容易被当成时序问题去改 RTL，白改几轮** |
| **② 结构问题** | 逻辑级数过多、扇出过大、组合穿透跨模块 | 改 RTL（打拍、复制寄存器、拆层次） |
| **③ 工具没使劲** | 约束正确、结构合理，只是综合 effort 不够 | 调综合选项 / 换策略，**优先于改 RTL** |

**判据**：一条违例路径，先问「这条路径**在功能上**需要在一个周期内跑完吗？」
答案是「不需要」→ 归①；答案是「需要但做不到」→ 归②。

### 第 3 步：按 ① → ③ → ② 的顺序处理

```
① 改 SDC（成本最低，影响最大）
     ↓ 还剩违例
③ 调综合策略（不动 RTL）
     ↓ 还剩违例
② 改 RTL 结构（成本最高，可能推翻验证结论）
```

**为什么这个顺序**：改 RTL 会**作废已验证的结论**（要重跑回归）。
改 SDC 和综合选项不会。所以能用前两者解决的，绝不进第三步。

> ⚠️ 改 RTL 之后必须回走一次 `../01_微架构与RTL编码/` 的清单，
> 并按 `../../02_流程与签核/RTL_Freeze.md` 的 ECO 规则更新基线。

### 第 4 步：记录分类结论

每一轮收敛，记下：这一轮改了哪类、动了什么、WNS/TNS 变化多少。
**没有这份记录，下一轮会重复上一轮的判断。**

## 检查清单

| 检查项 | 问题 |
|---|---|
| 时钟定义 | 每个时钟都有 `create_clock` 吗？生成的时钟有 `create_generated_clock` 吗？ |
| 跨域路径 | 异步跨域都设了 `set_false_path` / `set_clock_groups` 吗？ |
| 多周期 | 需要多个周期的路径设了 `set_multicycle_path` 吗？hold 侧也设了吗？ |
| 输入输出延迟 | `set_input_delay` / `set_output_delay` 与实际接口一致吗？ |
| 例外路径 | 每条 `set_false_path` 都有理由吗？（没有理由的 false path 是掩盖问题） |
| 组合穿透 | 跨模块组合路径记进约束了吗？ |

**多周期路径最常见的坑**：设了 setup 侧的 `-setup` 忘了 `-hold`，
结果 hold 检查按错误的边沿做，反而出现新违例。

## 坑

| 坑 | 为什么诱人 | 后果 |
|---|---|---|
| 看到违例就改 RTL | 「哪里慢就优化哪里」直觉合理 | 真正原因是约束漏了，RTL 白改，还作废了验证结论 |
| 用 `set_false_path` 消违例 | 一条约束违例就没了，报告立刻好看 | false path 是**声明这条路径不需要时序保证**，用错等于放弃时序 |
| 只看 WNS 不看 TNS | 一个数字好看 | WNS 达标但 TNS 很差，说明一大批路径都危险 |
| 多周期只设 setup | 忘了还有 hold | hold 违例，而且更隐蔽 |
| 不记录每轮改动 | 忙着收敛 | 下一轮重复判断，几轮下来没人记得改过什么 |

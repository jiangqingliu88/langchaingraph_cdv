## 1. M100 系统级架构

### 1.1 M100 SoC

- **8 个 LPDDR5X 子系统**：64 GB 内存，273 GB/s 峰值带宽。
- CPU 集群：**24 个 ARM Cortex-A78AE** 核，一致性 CMN 互连 + 共享末级缓存。
- MIPI-CSI（最多 11 路摄像头）、ISP、VPU、FSI（功能安全岛）、安全引擎、PMU/CRU、NPU Scheduler、Debug & Trace。

### 1.2 M100 NPU

```
┌───────────────────────────────────────────────────────────────┐
│  M100 NPU                                                     │
│                                                               │
│   ┌───────────────────────┐    2× AXI 主接口 (各 128 GB/s)     │
│   │  Central Control      │──► NoC → DDR / SoC 资源            │
│   │  Block (CCB)          │◄── AXI 从接口 (调度 CPU 命令)       │
│   │  · 4× SiFive X280 RISC-V                                │
│   │  · 4× 自定义向量引擎 (ICB 分发)                          │
│   │  · 32 MB SRAM (4×8 MB bank)                              │
│   │  · 2× DMA (DDR↔SRAM, DRB 广播权重)                       │
│   └─────────┬─────────────┘                                  │
│             │ ICB (Instruction Chain Bus, 菊花链)              │
│   ┌─────────▼─────────────────────────────────────────────┐  │
│   │ 14 × TPB 集群  (每集群 = 4 TPB + 共享 RISC-V CPU)        │  │
│   │  ┌──────┬──────┬──────┬──────┐  集群 NoC                │  │
│   │  │ TPB0 │ TPB1 │ TPB2 │ TPB3 │  + 共享 CPU/指令队列      │  │
│   │  └──────┴──────┴──────┴──────┘                         │  │
│   └─────────────────────────────────────────────────────────┘  │
│   · Mesh Bus: 点对点, 每对节点最高 256 GB/s                     │
│   · DRB: 广播, 聚合最高 256 GB/s                                │
└───────────────────────────────────────────────────────────────┘
```

- 实验使用 14 集群中的 12 个（86%），保留 2 个缺陷集群提升良率。
- UniAD 任务用 8 集群，其余 6 集群预留给座舱域功能。

## 2. 三级互连

| 互连 | 类型 | 带宽 | 用途 |
|------|------|------|------|
| **Mesh Bus** | 点对点可扩展 | 每对节点最高 256 GB/s | CCB / TPB 集群 / CPU / DMA / 块 SRAM 之间高带宽通信 |
| **DRB** (Data Ring Bus) | 确定性广播 | 聚合最高 256 GB/s | 多 TPB 多播（如权重广播），与 DDR 读带宽匹配 |
| **ICB** (Instruction Chain Bus) | 菊花链 | 64 bit/cycle | CCB → TPB 集群的指令分发 |

软件根据通信需求在 Mesh / DRB 间动态选择。

## 3. TPB 功能单元总览

| 单元 | 全称 | 职责 |
|------|------|------|
| **HBSM** | High Bandwidth Shared Memory | 2 MB 共享存储 + 功能单元间通信枢纽 |
| **TWU** | Tensor Walking Unit | 生成复杂非线性/嵌套循环地址序列（**无地址计算负担的核心**） |
| **TCU** | Tensor Computing Unit | 卷积 / 矩阵乘法 + 非线性激活流水线 |
| **CVU** | Configurable Vector Unit | 基本向量运算 / 池化 / Softmax / LayerNorm |
| **DTDU** | Data Transformation DMA Unit | TPB 内数据移动 + 广播 + 矩阵转置 |
| **GSDU** | Gather/Scatter DMA Unit | 不规则数据搬运（由集群 CPU 管理） |
| **CSU** | CPU Starter Unit | 触发中断请求集群 CPU 协助 |
| **SU** | Synchronization Unit | 管理本地/远程同步计数器（SC） |

## 4. TWU 规范（论文校准版）

> 论文原文（§5.2）：*"TPB 功能单元通过把输入数据流入、把输出数据流出，来访问存放在 HBSM 中的张量。
> 这要求系统生成适合特定计算模式的地址序列。对于卷积这类操作，地址往往不是简单的线性递增序列，
> 而是由嵌套循环定义的复杂非线性模式。"*

### 4.1 职责与配备

- 一个 TPB 功能单元通常有 **两个或更多输入 TWU**（读激活/权重）+ **一个输出 TWU**（写结果）。
- TPB 指令配置 TWU：指定**嵌套循环层数**，以及每层的 `Initial`、`Step`、`Final`。

### 4.2 三级 TWU 示例（论文图 10 对应）

```
[ 输入 TWU 0 ]   # 例：读取输入特征图
  Level_0 (最内层):  Initial=0   Step=1    Final=16
  Level_1 (第二层):  Initial=0   Step=16   Final=64
  Level_2 (最外层):  Initial=0   Step=256  Final=1024
                    [可选] 缓冲区偏移 Step（双缓冲，见 §4.4）
```

### 4.3 硬件走步规则（论文校准，形式化）

```
输入:  levels[0..L-1] = {Initial, Step, Final}   (levels[0] = 最内层)
       base_addr, buf_offset, buf_sel

初始化:
  for l in 0..L-1:  cnt[l] = levels[l].Initial
  buf_sel = 0

每次迭代 (功能单元请求地址):
  addr = base_addr + buf_sel * buf_offset
  for l in 0..L-1:  addr += cnt[l]
  输出 addr

  # 最内层无条件递增
  cnt[0] += levels[0].Step

  # 触顶判定 (从内向外)
  for l in 0..L-1:
    if cnt[l] >= levels[l].Final:
      cnt[l] = levels[l].Initial        # 触顶层下一次递增时从 Initial 重新开始
      if l+1 < L:
        cnt[l+1] += levels[l+1].Step    # 外层按自身 Step 递增
      else:
        完成 (所有层触顶)

  # 双缓冲 (可选)
  if 最外层触顶 and buf_offset > 0:
    buf_sel ^= 1
```

**规则要点（论文原文逐条对应）**：
1. **最内层规则**：最内层循环的 Value 计数器在每次迭代都**无条件递增**（递增量为 Step）。
2. **触顶触发更新**：每当某层 Value 达到其 Final 值，**外一层** Value 按该外层的 Step 递增。
3. **重置与回滚**：触顶的层在下一次递增时从 Initial **重新开始**。
4. **最终地址生成**：输出地址 = **所有循环层级 Value 计数器之和**（+ 基址 + 缓冲偏移）。

### 4.4 双缓冲（论文原文表述）

> 论文：*"TWU 还支持双缓冲地址生成。通过在外层循环指定**带缓冲区偏移的 Step 值**，
> 程序员便可以无缝地在两个缓冲区之间交替。"*

- **实现**：最外层 `Step` 携带 `buf_offset`（缓冲区偏移）；最外层触顶时基址整体偏移，`buf_sel ^= 1`。
- **流水线价值**：TCU 计算缓冲区 A 时，DTDU 利用总线空闲提前把下一批数据搬入缓冲区 B，
  消除数据搬运停顿，无需专用数据通路（HBSM 是通信枢纽）。

## 5. 同步单元 SU 与同步计数器 SC（论文校准版）

> 论文：*"同步是数据流并行计算中的关键组成部分……同步可以大幅简化：
> 一个代理在执行任务时更新自身执行状态；另一个代理监视第一个代理的状态，
> 据此决定是否继续。这种更新/监视关系可以双向存在。"*

### 5.1 核心机制（**SC 计数器，非信号量**）

- 每个 TPB 的 **SU** 管理一组**硬件同步计数器（SC）**。
- **更新（Update）**：功能单元占用一个计数器，在执行到 TPB 指令指定阶段时 `SC += 1`。
- **监视（Monitor）**：功能单元监视其他计数器，携带**期望值**；仅当 `SC >= 期望值` 时 SU 响应，否则暂停。
- 软件负责决定：哪些计数器被更新、哪些被监视、监视的期望值。

### 5.2 生产者-消费者（双向）

```
生产者                         消费者
  │ 写入预分配缓冲区             │
  │ SC[prod]++  ←数据可用信号     │
  │                             │ 监视 SC[prod] ≥ 期望值 → 开始处理
  │                             │ SC[cons]++  ←空间已释放
  │ 监视 SC[cons] ≥ 期望值 → 继续 │
```

### 5.3 其他同步模式

- **屏障（Barrier）**：确保一组 TPB 完成各自当前指令后再继续（CCB 支持，用于不频繁的全局同步点）。
- **广播（Broadcast）/ 归约（Reduce）**：多芯片配置下也适用。

### 5.4 SU 指令字段（位级扩展）

| 字段 | 位宽 | 语义 |
|------|------|------|
| `sc_update_id` | 8 bit | 本指令完成后更新的 SC ID |
| `sc_update_stage` | 4 bit | 更新触发的执行阶段 |
| `sc_monitor_id` | 8 bit | 监视的 SC ID |
| `sc_monitor_expect` | 16 bit | 监视期望值 |
| `sc_mode` | 2 bit | 0=更新, 1=监视, 2=更新+监视 |

## 6. TPB 指令（论文语义 + 位级布局扩展）

### 6.1 论文语义

> 论文：*"TPB 指令定义张量操作，并携带**张量形状**和**通信需求**等丰富元数据。
> 每条指令可能长达数千比特，以 64 bit/cycle 传输时需要数百个周期，
> 而执行时间通常长达数万个周期，因此指令分发不会成为瓶颈。"*

- **执行顺序**：同一 TPB 的同一功能单元内保持顺序；不同 TPB 之间允许乱序完成；
  依赖由**软件管理同步**（SU/SC）。
- **派发**：CCB 的 4 对 RISC-V 核 + 自定义引擎解析并转发大型复杂 TPB 指令；
  指令可经**目的掩码广播**到多个 TPB。

### 6.2 指令字布局（位级扩展，兼容论文语义）

```
┌────────────┬───────────────────┬──────────────────────┬────────────┐
│ 头部        │  TWU_CONFIG_BLOCK │  SU_SYNC_CFG          │  FUNC_CFG   │
│ OPCODE(8b) │  TLV 流 (TWU 嵌套) │  SC 更新/监视配置      │ 算子参数    │
│ PKT_LEN(16b)│                    │                       │ (形状/通信) │
└────────────┴───────────────────┴──────────────────────┴────────────┘
```

| 段 | 字段 | 语义 |
|----|------|------|
| 头部 | `OPCODE` | 目标功能单元：0=TCU, 1=CVU, 2=DTDU, 3=CSU, 4=SU(同步) |
| 头部 | `PKT_LEN` | 指令总长度（bit） |
| 头部 | `dst_mask` | 目的 TPB 掩码（广播到多 TPB） |
| 头部 | `tensor_shape` | 张量形状元数据（M/K/N 或 H/W/C 等） |
| 中部 | `TWU_CONFIG_BLOCK` | 所有 TWU 的嵌套循环（TLV 编码） |
| 中部 | `SU_SYNC_CFG` | SC 更新/监视配置（§5.4） |
| 后部 | `FUNC_CFG` | 算子参数（精度、激活、通信需求等） |

> 注：GSDU **不直接执行 TPB 指令**（由集群 CPU 管理，见 §10）；
> 因此 OPCODE 仅覆盖直接执行 TPB 指令的 TCU/CVU/DTDU/CSU。

## 7. TCU：张量计算单元（OPCODE = 0）

### 7.1 硬件

- **8×64 MAC 二维阵列**；每 MAC 每周期执行 **4 对**激活×权重点积。
- 激活行方向复用，权重列方向复用。
- 32×32 / 32×64 矩阵乘在 **32 周期**完成（1 字节元素宽度时匹配
  激活 32B/cycle、权重 64B/cycle 输入带宽）。
- 部分和 → 输出缓冲区 → 非线性激活流水线 → 写回 HBSM。
- **双缓冲**：持续保持峰值吞吐。
- 大张量：外层循环控制逻辑按块遍历源张量。

### 7.2 FUNC_CFG

| 字段 | 位宽 | 语义 |
|------|------|------|
| `tcu_op` | 4 bit | 0=MATMUL, 1=CONV2D, 2=POOL, 3=其他收缩 |
| `M/K/N` | 各 16 bit | 收缩维度 |
| `kernel_h/w`、`stride_h/w`、`pad_h/w` | 8/8/4/4/4/4 | 卷积参数 |
| `dtype` | 4 bit | 0=int8, 1=bf16, 2=fp16, 3=fp32 |

### 7.3 CONV2D 滑窗 TWU 配置示例

```
TCU.CONV2D  M=H*W, K=C*kh*kw, N=Co, kernel=3x3, stride=1, pad=1
  Input_TWU_A (滑窗展开):
    L0: Init=0 Step=1    Final=3       # kw
    L1: Init=0 Step=W    Final=3       # kh (跨行)
    L2: Init=0 Step=1    Final=Cin     # 通道
    L3: Init=0 Step=W*Cin Final=H*W    # 空间位置 (滑窗)
  Input_TWU_B (权重):
    L0: Init=0 Step=1 Final=3
    L1: Init=0 Step=3 Final=3
    L2: Init=0 Step=9 Final=Cin
    L3: Init=0 Step=Cin*9 Final=Co
  Output_TWU_C:
    L0: Init=0 Step=1 Final=Co
    L1: Init=0 Step=Co Final=H'*W'
    最外层 Step 携带缓冲区偏移 → 双缓冲输出
```

## 8. CVU：可配置向量单元（OPCODE = 1）

### 8.1 硬件

- 若干**单一功能的向量算术算子**；每个算子接收 1–2 个输入向量流，产生 1 个输出向量流。
- TPB 指令可把输入流路由到单个算子，或**组合多算子 + 中间缓冲成多级流水线**。
- 示例：Softmax 配置（论文图 12 底部）——多级流水线完成 exp / sum / divide。
- 无法完全流水化的复杂操作：拆成多阶段，用不同 TPB 指令处理。

### 8.2 FUNC_CFG

| 字段 | 位宽 | 语义 |
|------|------|------|
| `cvu_op` | 8 bit | 0=ADD, 1=MUL, 2=RELU, 3=POOL, 4=SOFTMAX, 5=LAYERNORM |
| `vec_len` | 16 bit | 向量长度 |
| `lane_width` | 4 bit | lane 位宽 |
| `pipeline_cfg` | 16 bit | 多算子流水线配置（算子链） |

## 9. DTDU：数据变换 DMA 单元（OPCODE = 2）

### 9.1 职责

- **像计算单元一样执行 TPB 指令**。
- HBSM 内部数据移动、**矩阵转置**等布局变换、预定义值填充（存储初始化）。
- 支持跨 TPB 广播。

### 9.2 FUNC_CFG

| 字段 | 位宽 | 语义 |
|------|------|------|
| `dtdu_op` | 4 bit | 0=MOVE, 1=TRANSPOSE, 2=FILL, 3=BROADCAST |
| `src_base` / `dst_base` | 各 32 bit | 源/目标 HBSM 地址 |
| `elem_width` | 4 bit | 数据宽度 |
| `transform` | 8 bit | 布局变换类型 |

## 10. GSDU：Gather/Scatter DMA 单元（由集群 CPU 管理）

> 论文：*"GSDU 由集群 CPU 管理，并不直接执行 TPB 指令。它负责那些难以编码进标准
> TPB 指令的不规则数据移动模式。一条 TPB 指令会触发 CSU，由后者启动 CPU 例程来控制 GSDU。"*

### 10.1 工作机制

```
TPB 指令 (CSU 触发)
  → CSU 保存任务参数, 触发中断
  → 集群 CPU 中断服务例程取回参数
  → CPU 经 VCIX 接口控制 GSDU (gather/scatter)
  → 例程完成 → 通知 CSU → CSU 把对应 TPB 指令标记为结束
```

- 作用域：本地 HBSM ↔ 外部存储（其他 TPB HBSM / CCB SRAM / DDR）。

### 10.2 CPU 侧控制（寄存器级）

| 寄存器 | 语义 |
|--------|------|
| `GSDU_CTRL` | 启动 / 模式（gather/scatter） |
| `GSDU_SRC` / `GSDU_DST` | 源 / 目标基址 |
| `GSDU_IDX` | 索引表基址 |
| `GSDU_LEN` | 搬运长度 |

## 11. CSU：CPU 启动单元（OPCODE = 3）

> 论文：*"CSU 通过执行一条 TPB 指令来触发中断，从而请求集群 CPU 协助完成某项任务。
> 任务参数保存在 CSU 中，CPU 的中断服务例程取回参数，判断需要执行的操作。"*

### 11.1 机制

- 触发中断 → 集群 CPU（SiFive X280 向量 CPU，VCIX 扩展）协助。
- 任务类型：标量处理、向量处理、经 VCIX 控制 GSDU 的数据移动。
- 最多 4 个 TPB 同时请求，CPU 仲裁按顺序处理。
- 使 CPU 操作与张量操作遵循**相同指令语义**，简化编译/调度/分发。

### 11.2 FUNC_CFG

| 字段 | 位宽 | 语义 |
|------|------|------|
| `csu_task_id` | 8 bit | 任务 ID（对应 CPU 服务例程） |
| `csu_cpu_req` | 2 bit | 请求类型（0=标量, 1=向量, 2=GSDU） |
| `param_ptr` | 32 bit | 任务参数在 HBSM 的地址 |

## 12. HBSM：高带宽共享内存

- **2 MB**，32 个存储 bank，每 bank 每周期 32 字节 → 峰值带宽高。
- 地址以 **32 字节粒度**在 bank 间交错；**8 个请求端口**。
- 轮询仲裁，保证同一请求者内部顺序。
- 同步动作（标记数据已生产/已消费）**附着在存储访问之上**，请求赢得仲裁时触发，
  之后全局可见 → HBSM 是数据流体系结构的 central backbone。
- 约 20 周期访问延迟（流式特性下不致命）。

## 13. 完整业务闭环：双缓冲流水线卷积算子

### 13.1 CCB 下发 TPB 指令

```
头部:  OPCODE=0 (TCU)  dst_mask=0b0001 (TPB0)
       tensor_shape: M=1024 K=432 N=64, kernel=3x3, stride=1, pad=1, dtype=bf16
TWU_CONFIG_BLOCK:
  Input_TWU_0 (特征图): L0..L3 滑窗循环 (§7.3)
  Input_TWU_1 (权重):   L0..L3
  Output_TWU  (结果):   L0..L1 + 最外层 Step 携带缓冲偏移 (双缓冲)
SU_SYNC_CFG:
  sc_monitor_id=5, expect=1     # 等 DMA 搬完缓冲区 A (SC5 ≥ 1)
  sc_update_id=6                # 完成后 SC6++
FUNC_CFG: tcu_op=CONV2D, M/K/N, kernel, stride, pad, dtype
```

### 13.2 物理运行轨迹（论文校准）

1. CCB 的 RISC-V 核解析 TPB 指令，经 ICB 发送到 TPB0；集群指令队列缓存。
2. 功能单元就绪即取指；TCU 的 SU 监视 `SC5 ≥ 1`（DMA 搬完缓冲区 A 后 `SC5++`）。
3. TCU 输入 TWU 生成滑窗地址，TCU 从 HBSM 缓冲区 A 计算第一块卷积。
4. 最外层循环触顶：TWU 基址整体偏移缓冲偏移（切到缓冲区 B），`buf_sel ^= 1`。
5. 切换瞬间 DTDU 利用总线空闲，把下一批数据搬入缓冲区 A。
6. TWU 遍历完所有地址，TCU 输出经激活流水线写回 HBSM。
7. SU 检测所有层 Final 满足；`SC6++` 通知下游；必要时触发中断。

### 13.3 时序图

```
Clk  │ SC5 │ TWU走步(A)  │ TCU计算(A) │ buf切换 │ TWU走步(B) │ TCU计算(B) │ SC6/INT
─────┼─────┼─────────────┼────────────┼─────────┼────────────┼────────────┼──────
     │ _/‾ │             │            │         │            │            │
     │     │ ████████████ │  ████████  │         │            │            │
     │     │             │            │  buf↑  │ ████████████ │  ████████  │
     │     │             │            │         │            │            │  _/‾
     │     │ (DTDU 搬入 B)            │ (DTDU 搬入 A)         │            │
```

## 14. 编译器与运行时软件栈

### 14.1 编译工具链（三层）

```
神经网络子图
  → 时空调度器: 子图→TPB 映射; 大张量→迷你张量, 沿数据流流水线传递 (§图14)
```

## 16. 附录

### 16.1 术语映射表（v4.0/v6.0 → v7.0 论文校准）

| 旧术语 | 论文术语 | 说明 |
|--------|----------|------|
| CIQ 分发 | CCB RISC-V 核 + ICB 分发 | 4 对 X280 + 自定义引擎；集群有指令队列 |
| 信号量 SV (P/V) | 同步计数器 SC (更新/监视) | SU 管理；监视带期望值，`SC ≥ 期望` 才响应 |
| DRBN | DDR + CCB SRAM + 其他 TPB HBSM | 由 DTDU/GSDU 搬运 |
| GSDU 执行 TPB 指令 | GSDU 由集群 CPU 管理 | CSU 触发 → CPU 例程经 VCIX 控制 |
| CSU 收 RISC-V 扩展指令 | CSU 触发中断请求 CPU 协助 | 参数保存在 CSU，CPU 取回 |
| TTU_SYNC_HEADER | 指令头部 + SU_SYNC_CFG | 同步段承载 SC 更新/监视 |
| 紫线 | 中断（CCB/主机 CPU 可配置） | 论文未提"紫线"名称 |

| `0x02` | TWU_BLOCK_START | 2 B | 角色 ID (0=in0,1=in1,2=out) + 层级数 |

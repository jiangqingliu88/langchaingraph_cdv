## 1. M00 验证契约方法学总纲

**目的**：统一语言，定义契约全景、五手段分工、四维完备性、生命周期。

**章节大纲**：
1. 目的与范围
2. 术语：契约、契约矩阵、associate view、CG/SCB/SVA/Checker、assume/guarantee/check/cover/measure/gate
3. 契约全景：功能/接口/时序性能/配置/资源/异常/数据/可观测/低功耗/环境/流程/复用/形式化/软硬件/并发/集成/可靠性/CDC/元契约/配置组合/版本兼容/回归
4. 五手段分工：CG 度量、case 激励、SCB 结果、SVA 时序、Checker 规则
5. 契约分层：需求→事务→接口→实现；锚点选择
6. 四维完备性：对象×形态×粒度×生命周期
7. 契约生命周期：发现→定义→实现→校验→维护→签核
8. 保障方式：规则/LLM/人三色
9. 门禁体系：矩阵门禁/视图门禁/回归 CI 门禁
10. 与项目 vplan 的关系

**关键产出**：术语表、契约全景图、五手段职责表、四维自评表。

**验收标准**：全员对“契约/矩阵/视图/五手段/三色”理解一致；能回答“一个 Feat 怎么落到契约再到 case”。

## 2. M01 覆盖率组设计指南

**目的**：教怎么按功能契约划分 CG，不按 RTL 模块划分。

**章节大纲**：
1. 设计思想：需求/功能契约→CG→覆盖点→bin→约束→case→种子闭环
2. 分组原则：单一功能契约、需求可追溯、可采样、可激励、组内可交叉、组间低耦合、粒度适中、区分“发生”与“正确处理”
3. 从零设计步骤（10 步）：写组信息→列覆盖点→定义 bin→组内交叉→跨组交叉汇总→采样位置→约束映射→批次映射→追溯矩阵→签核标准
4. 覆盖点类型：枚举/水位边界/状态路径/资源占用/时序握手/异常/配置/性能/参数
5. 交叉设计：有意义才交叉；ignore_bins 审批
6. 采样原则：monitor 采样、iff 有效周期、联合采样、illegal_bins
7. 反例清单：按 RTL 分组、只采激励、按地址判冲突、漏 NIU 特例等
8. 模板：CG 信息表、覆盖点表、交叉表、约束映射表

**示例**：以 CMD_SCH 10 个 CG 为样例，但明确“示例不是标准，按项目功能契约派生”。

**验收标准**：每个 CG 有需求 ID、覆盖点、交叉、约束映射、采样位置、批次；无孤立覆盖点。

---

## 3. M02 Case 分解与批次演进指南

**目的**：明确 case 是激励契约，不按 CG 一一写 case。

**章节大纲**：
1. Case 与 CG 多对多关系
2. Case 分解维度：基础功能/指令类型/缓存队列/依赖/并行调度/存储资源/返回值握手反压/异常中断/性能CSR/随机混合
3. Sequence/场景设计：raw_chain、barrier、ls_parallel、tmu、illegal、bp、third_inst、tile_map、rsp_rmw、int_info
4. 约束三层：指令生成/序列依赖/场景定向；约束与覆盖点一一对应
5. 批次规划：由上一批缺口驱动；目标覆盖率演进
6. 种子管理：基线建立 7 步、平台期、种子表、分级工具
7. 缺口回灌：缺口→根因→约束/场景→更新 case 契约
8. 反例：一 CG 一 case、只定向不随机、force 内部信号

**模板**：case 分解表、批次表、种子基线表、缺口回灌表。

**验收标准**：每个 bin 有约束/场景可命中；批次由缺口驱动；种子基线由平台期决定并纳入回归。

## 4. M03 契约矩阵指南（本体）

**目的**：建契约台账，作为权威源。

**章节大纲**：
1. 矩阵与视图关系：本体 vs associate view；多对多
2. 矩阵清单：15 类（需求/功能/接口/时序性能/配置/资源/异常/数据/可观测/低功耗/环境/流程/复用/形式化/软硬件）+ P0/P1 扩展（并发/集成/可靠性/CDC/元契约/配置组合/版本/回归/文档）
3. 行字段：contract_id、category、content、form、authority、check_method、owner、stability、fail_mode、gate、feat_ids、status、保障方式（绿/黄/红）
4. ID 规范：`C-类别-子类-序号`，全局唯一稳定
5. 形态：assume/guarantee/check/cover/measure/gate
6. 维护：版本化、变更记录、owner 评审
7. 矩阵门禁：唯一 ID、字段齐全、Feat 映射、无孤立契约

**模板**：契约矩阵表、契约登记表。

**验收标准**：每个契约有权威源、可判定语义、独立基准、可观测环境、owner、gate；无孤立契约/孤立需求。

## 5. M04 用例视图契约指南（associate view）

**目的**：每个 case 声明引用哪些契约、挂哪些实例、运行证据、通过判据。

**章节大纲**：
1. 定位：关联视图，不替代矩阵
2. 字段：case_id/test_name/batch/contract_refs/cg_activate/target_bins/scb_mount/sva_bind/checker_trigger/sequences/constraints/pass_criteria/seed_baseline/pre_config/runtime_evidence/fail_class/status
3. 三种载体：登记表、YAML/JSON、UVM test 内注册
4. 挂载原则：按契约引用挂载，不全挂；挂载≠激活，门禁校验激活次数>0
5. 运行时校验：声明 vs 实际对比报告；不一致分类
6. 失败分类与定位：CG 未命中/SCB 比对 0/SCB mismatch/SVA 触发 0/SVA fail/Checker 检查 0/Checker violation
7. 视图门禁：声明完整、运行一致、多激活补声明、少激活查挂载
8. 缺口回灌入口：缺口→查视图→查 case→补约束/种子

**模板**：case 契约 YAML 模板、运行报告模板、不一致分类表。

**验收标准**：每个 case 至少引用一个契约、挂一类检查；声明 bin 100% 命中；SCB/SVA/Checker 激活次数>0 且 0 失败。

## 6. M05 SCB/SVA/Checker 契约分工指南

**目的**：结果/时序/规则三权分立，不重叠不遗漏。

**章节大纲**：
1. 三权分立：SCB 结果、SVA 时序、Checker 规则
2. SCB：数据/状态/计数/顺序/资源不泄漏；独立参考模型、参数化、按 tag 比对
3. SVA：握手/反压保持/start-done-rls/互斥/状态机/中断/TMU 仲裁/链表
4. Checker：编码合法性/参数合法性/跨模块约定/配置规则/地址空间/资源规则/NIU 规则
5. 边界：SCB 不做时序，SVA 不做数据比对，Checker 不做覆盖度量
6. 冗余策略：主/辅明确，失败以主定位
7. 契约归属表：功能契约→三手段映射
8. 失败定位：先看 CG 是否命中，再看三手段

**模板**：契约归属表、断言清单、Checker 规则清单。

**验收标准**：每个功能契约至少一个主检查；三手段无职责重叠；失败可定位。

---

## 7. M06 跨 DUT 契约复用与适配指南

**目的**：DUT 变化时契约不漂移。

**章节大纲**：
1. 契约分层：需求/事务/接口/实现；只依赖前两层
2. 适配机制：adapter、monitor 分模块、参考模型参数化、bind SVA、checker 参数化
3. 契约版本化：CG/case/模型/SVA/Checker 版本
4. 变更影响分析：内部实现/接口/协议/功能/删功能五类
5. 配置同源：DUT/环境/参考模型配置对象统一
6. 契约测试：接口/事务/CG/模型/SVA/Checker 契约测试
7. 门禁：契约测试+回归门禁+覆盖率合并

**模板**：契约分层表、变更影响分析表、契约测试清单。

**验收标准**：接口变化只改 adapter/bind；内部重构只改 monitor 适配；配置变化参考模型同源；契约测试全过。

## 8. M07 契约完备性评估指南

**目的**：回答“契约够不够”。

**章节大纲**：
1. 四维判据：对象/形态/粒度/生命周期
2. 自评表：每项 0/1/2 打分；2=显式且有门禁
3. 缺口清单：P0 并发/集成/元契约/配置组合；P1 可靠性/E2E/协议/版本/CI/文档/形式化；P2 功能安全/信息安全/PPA/DFT
4. 形态均衡：assume/guarantee/measure/gate 补强
5. 粒度缺口：系统级集成、元契约、信号到事务映射
6. 生命周期缺口：设计期 assume、集成期 guarantee 组合、复用期兼容
7. 补齐路线：P0→P1→P2，排期与依赖
8. 门禁：自评≥阈值才允许签核

**模板**：完备性自评表、缺口登记表、补齐路线图。

**验收标准**：自评可量化；缺口有 owner/排期；P0 补齐后才签核。

## 9. M08 P1 非功能契约补齐指南

**目的**：把 P1 七类契约落地。

**章节大纲**：
1. 七类矩阵：可靠性/容错、数据 E2E、协议合规、版本兼容、回归/flake/CI、文档一致性、形式化 assume/guarantee 组合性
2. 每类契约条目示例（可直接引用 CMD_SCH 的 C-REL/C-DATA/C-PROT/C-VER/C-REG/C-DOC/C-FV）
3. Case 视图挂载：monitor_mount/script_gate/fv_props/runtime_evidence
4. 三层门禁扩展
5. 排期：2~3 周三批
6. 风险与依赖：无错误注入/无 VIP/无多版本/形式化人力
7. 豁免策略：无机制时写 assume 或豁免，不假装覆盖

**模板**：P1 七类矩阵、P1 case 视图字段、P1 门禁清单。

**验收标准**：七类矩阵建立；每契约被 case/脚本引用；可靠性/E2E/协议用例通过；版本/CI/文档脚本接入；形式化关键属性 prove。

## 10. M09 契约保障方式指南（规则/LLM/人）

**目的**：明确谁保证契约，避免全靠规则/LLM/人。

**章节大纲**：
1. 分层分工：规则兜底、LLM 加速、人拍板
2. 生命周期分工：发现/定义/实现/校验/维护/签核
3. 契约类别适配度表
4. 三色标注：绿（规则）/黄（LLM+人审）/红（人定义签核）
5. 硬规则：LLM 输出必须人审+规则校验；规则全绿不等于契约正确；签核豁免不 delegation
6. 风险：规则漏语义、LLM 幻觉、人漏/漂移
7. CMD_SCH 三色示例

**模板**：三色标注表、保障方式登记表。

**验收标准**：每行契约标保障方式；LLM 产出有审记录；签核/豁免有人签字。

## 11. M10 契约本源与门禁指南

**目的**：回答“契约凭什么成立、怎么持续成立”。

**章节大纲**：
1. 六类本源：权威源、可判定语义、独立基准、可观测/可控环境、组织授权、闭环证据
2. 缺本源退化表
3. 门禁三层：矩阵门禁（本体完整性）、视图门禁（关联一致性）、回归/CI 门禁
4. 签核条件：覆盖 100%/illegal 0/ignore 审批/追溯无孤立/种子基线/回归稳定/豁免记录
5. 豁免流程与记录表
6. 变更管理：DUT 变更→影响分析→追溯矩阵→回归
7. 版本化与交付物

**模板**：本源检查表、门禁清单、豁免记录表、签核表。

**验收标准**：每个契约可回答“依据哪份文档哪一条、什么算对、怎么观测、谁负责、怎么证明持续成立”；三层门禁全绿才签核。

## 14. 落地顺序与门禁

**第 1 周（MVP）**：M00 + M01 + M03 + M04 + M10 + T00 核心模板。  
产出：术语统一、契约矩阵骨架、case 视图模板、门禁清单。

**第 2~3 周**：M02 + M05 + M07。  
产出：case 分解/批次/种子、三权分立、完备性自评。

**第 4~6 周**：M06 + M08 + M09。  
产出：跨 DUT 适配、P1 七类、三色保障。

**门禁**：
- 文档评审通过；
- 矩阵/视图/门禁模板在 CMD_SCH 试点跑通；
- P1 七类至少各一条契约落地；
- 完备性自评≥阈值；
- 签核表可执行。

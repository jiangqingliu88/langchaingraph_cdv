专利名称：面向集成电路功能验证的基于多智能体的可审计签核与证据包生成系统及方法

技术领域

本发明涉及人工智能辅助软件系统，尤其涉及一种用于集成电路（IC）功能验证与签核的基于多智能体（Agent）协同执行、工具受控、并可生成可审计证据包的系统与方法。

背景技术

IC 功能验证流程通常涉及规格分析、验证环境搭建、测试用例生成、回归执行及最终签核等多阶段工作。现有技术中，人工审阅耗时且难以追溯；通用代码生成/补全工具虽然能生成部分代码或文本，但缺乏面向验证流程的角色分工、质量门槛、工具级别的参数校验及统一证据链导出能力，不能满足工程化签核与合规审计的要求。

发明内容

本发明的目的是提供一种面向 IC 功能验证的多智能体签核系统与方法，该系统将智能体按角色（例如规格规划、验证架构、回归管理、调试、证据汇总、报告生成等）明确划分，每个智能体声明其对共享上下文的“消耗（consumes）”与“产生（produces）”契约，采用工具注册与 schema 验证机制控制外部工具调用风险，自动执行质量自检（静态检查、编译、闭环回归等），并在每次执行后生成包含输入、输出、工具调用记录、产物哈希与质量报告的证据包（manifest），以便 Sign‑off 经理进行审批与审计。

为实现上述目的，本发明提出如下若干方面的技术方案：

一项面向 IC 功能验证的系统，该系统包括：
- 智能体注册模块，用于注册多个智能体角色及其实现类；
- 基础智能体模块，定义智能体生命周期、LLM 实例创建、`consumes`/`produces` 上下文契约、质量评分、重试与观察者（Observer）接口；
- 工具管理模块，包含工具注册中心（ToolRegistry），用于定义工具的输入 schema、风险等级，并在调用前进行参数校验；
- 沙箱（Sandbox）模块，用于根据工具风险等级控制执行许可（自动批准、人工批准或阻断）；
- 执行编排模块，用于按流水线阶段将智能体组织为任务流并触发执行；
- 质量自检模块，用于对生成的验证环境与测试产物执行静态检查、编译检查与闭环回归检查，并生成结构化的质量报告；
- 证据与清单（Manifest）生成模块，用于收集执行输入/输出、工具调用日志、文件哈希与质量报告，并生成可导出的证据包；
- 签核与审计模块，包含 Signoff 数据模型、审批 API、RBAC 权限控制与审计日志记录，用于 Sign‑off 经理对证据包进行审批或驳回。

所述系统进一步包括：与编辑器集成的规格元数据校验器，用于在保存规格文档（例如 Markdown）时对头部 metadata（id、version、owners、interfaces、dependencies 等）进行 schema 验证并将结构化数据导出为 JSON/YAML 供智能体消费；以及用于从证据包生成摘要视图并按风险优先级排序的报告生成器。

本发明还提供一种与上述系统相配套的方法，包括如下步骤：
1. 在规格编辑器中创建或更新规格文档，并在保存时对文档头部元数据执行 schema 校验；
2. 启动以 `SpecAndTestPlanner` 为代表的规格分析智能体，通过 LLM 与辅助工具生成结构化规范与测试点；
3. 启动 `VerificationArchitect` 智能体，基于结构化规格调用 Jinja2 模板或其它生成器生成验证环境代码，并调用质量自检工具链生成质量报告；
4. `RegressionManager` 智能体运行回归试验，收集日志并将运行结果写入证据仓库；
5. 证据生成模块聚合输入、输出、工具调用日志、质量报告及产物哈希，生成 manifest 文件并将相关产物打包为证据包；
6. Sign‑off 经理通过签核界面查看证据摘要与风险排序，并根据可编程的签核策略执行 Approve/Reject 操作；
7. 审计模块记录所有审批动作、时间戳与证据包哈希，确保全流程可追溯。

有益效果

与现有技术相比，本发明具有如下有益效果：
- 将验证流程工程化、角色化，减少人工审阅工作量；
- 通过工具 schema 验证与沙箱策略降低自动化调用风险；
- 提供质量门槛与自动修复迭代机制，提升交付可靠性；
- 生成可导出、可验证的证据包，便于签核、审计与合规；
- 支持按项目隔离、RBAC 与可编程签核策略，便于在工业环境中集成部署。

实施例（示范性）

下面结合附图和具体实施例对本发明作进一步说明（此处示例性说明，非限制性）：

实施例 1 — 系统部署与典型流程
- 在服务器上部署本系统，配置项目根目录与允许的工具执行路径；
- 开发者/工程师在集成的 Markdown 编辑器中编辑规格文档，保存时自动触发 schema 校验；
- 工程师提交“生成环境”任务，`SpecAndTestPlanner` 解析规格并生成结构化 spec；
- `VerificationArchitect` 通过工具链渲染 UVM 骨架并执行质量自检（静态、编译、loopback）；
- 系统生成 `quality_report.json` 与 `manifest.json`；
- Sign‑off 经理在签核工作台查看摘要并审批；审批记录写入 `AuditLog`。

实施例 2 — 工具调用与沙箱策略
- 某生成步骤需要写磁盘文件，相关工具在注册时被标记为 `risk_level: write`；
- 在调用时，Sandbox 根据 `write` 策略提示人工确认或自动批准；
- 调用结果（包括命令、返回码、stdout/stderr）被记录并纳入证据包。

说明书摘要

本发明公开了一种面向 IC 功能验证的多智能体签核系统与方法，系统通过将验证任务拆分为具备 `consumes`/`produces` 契约的智能体，结合工具 schema 验证与沙箱执行控制，实现自动化的环境生成、质量自检与证据包导出，支持由 Sign‑off 经理完成最终审批与审计记录，提升签核效率并保证可追溯合规性。

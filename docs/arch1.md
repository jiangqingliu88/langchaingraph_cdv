  2. 架构层面：12-agent 流水线 vs 单 agent

  这才是你真正在问的。让我客观分析：

  当前架构：12 个专职 Agent 串行流水线

  spec_planner → design_architect → verify_architect → model_agent → write_rtl
      → test_engineer → assertion_engineer → coverage_manager
      → regression_manager → debug_engineer → quality_assurance → report_generator

  优势：
  - 每个 Agent 职责单一，prompt 可以高度专业化
  - 每个阶段产出独立 artifact，天然形成证据链
  - 失败隔离——某个阶段挂了可以单独重试
  - 跟你的 CLAUDE.md 愿景（可复现、可审计、可治理）完全对齐

  劣势：
  - 12 次 LLM 调用，延迟 ×12，Token 消耗 ×12
  - 上下文传递损耗——前一阶段的 nuance 在后一阶段可能丢失
  - 维护成本——12 个 main.py 要保持一致
  - 对简单模块（比如一个只读寄存器模块）来说过度设计

  单 agent 方案：一个 Agent 干全部

  优势：
  - 一次 LLM 调用，延迟和 Token 都低
  - 上下文不丢失
  - 代码量少，维护简单

  劣势：
  - 长链路可靠性极差——LLM 在 10+ 步之后必然漂移
  - 无法独立重试某个阶段
  - 无法形成分阶段证据链
  - 跟你的项目愿景（签核平台）矛盾

# SignOffAI 决策闭环架构（五层）

> 本文档描述 `src/layers_engine/l3_decision/` 的架构分层、职责边界与数据流。
> 决策链路：spec → 生成 → 编译 → 回归 → 覆盖率 → L3 决策 → 动作执行 → 修复 → 迭代 → 签核。

## 1. 分层总览

```
┌─────────────────────────────────────────────────────────────────┐
│ driver.py  ── 决策闭环编排层（只做迭代循环 + 状态流转 + agent 路由）│
├─────────────────────────────────────────────────────────────────┤
│ domain/    领域执行层（真实 EDA 操作 + LLM 修复，从 driver 拆出）  │
│  ├─ generator.py   spec→UVM / design→RTL / model→参考模型         │
│  ├─ regression.py  编译 / 回归 / 覆盖率执行 / force_rebuild       │
│  ├─ fixer.py       debug/verify agent 修复（minimal fix 协议）    │
│  └─ analyzer.py    coverage gap 归因 / audit 签核                │
├─────────────────────────────────────────────────────────────────┤
│ 决策引擎  CoverageDrivenDecisionEngine（L3）                     │
│  ├─ decide(Observation) → Action（规则 + L5 experience 记忆）     │
│  └─ Observation: coverage/gaps/uncovered_bins/failed_tests/...   │
├─────────────────────────────────────────────────────────────────┤
│ 底层工具  src/tools/lib/*（EDA 编译/回归/协议注入/LLM 调用）       │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 7 个 agent 的职责与接入点

| agent | 职责 | 接入点 | 产物 |
|-------|------|--------|------|
| **design** | RTL 生成 | `generator.generate_rtl` | apb_uart.sv（LLM + 三重门禁，失败回退确定性模板） |
| **model** | 参考模型 | `generator.generate_model` | apb_uart_ref.sv（vlog 门禁） |
| **verify** | UVM 环境修复 | `fixer.debug_fix_files`（agents/env/bench 文件） | 修复指令 JSON |
| **ops** | EDA 执行 | `regression.run_compile/run_full_regression` | 编译/回归/覆盖率 |
| **coverage** | 覆盖率归因 | `analyzer.coverage_gap_analysis` | uncovered_bins/gaps → L3 |
| **debug** | 失败修复 | `fixer.debug_fix_files`（rtl 等文件） | 修复指令 JSON |
| **audit** | 签核意见 | `analyzer.run_signoff` | report.json + audit_opinion |

## 3. 数据流（一回合）

```
spec.md
  → generator.generate_uvm     spec.json → YAML → UVM 骨架（确定性工具链）
  → generator.generate_rtl     design agent 写 RTL → vlog+vopt+prdata 门禁
  → generator.generate_model   model agent 写参考模型 → vlog 门禁
  → regression.run_compile     ops agent 编译（errors=0 才继续）
  → regression.run_full_regression  ops agent 回归 + vcover 覆盖率
  → analyzer.coverage_gap_analysis   coverage agent：vcover details → LLM gap 归因
  → CoverageDrivenDecisionEngine.decide(Observation) → Action
  → driver._exec_action        执行动作（扩种/定向激励/重试）
  →（失败时）fixer.debug_fix_files  debug/verify agent 读日志 → minimal fix → 重编译/重回归
  → 循环直到 CONVERGE 或 max_rounds
  → analyzer.run_signoff       audit agent 意见 + report.json + manifest.json
```

## 4. 关键设计决策

### 4.1 EDA 是唯一真理（门禁）
- RTL 必须过 **vlog 编译 + vopt 优化 + prdata 组合输出** 三重门禁
- vopt 能抓多驱动（vopt-7061），prdata 检查防 predictor 组合模型与寄存输出时序差一拍
- LLM 产物不过门禁 → 回退确定性模板（design/model agent）

### 4.2 只改错误行，不重写整个文件（minimal fix 协议）
- debug/verify agent 输出修复指令 JSON：`{"fixes": [{file, line, old, new}]}`
- 应用时：line + old 锚精确匹配，±3 行保护，防整文件重写破坏跨文件契约

### 4.3 passive agent（monitor-only）
- 中断/状态类接口（DUT 输出）生成 `UVM_PASSIVE` agent：无 driver、无 sqr
- env/test/virtual_sequencer 模板按 `is_active` 条件化（避免 vsim-8440 驱动 DUT 输出）

### 4.4 predictor 寄存器模型（动态生成）
- 从 spec 寄存器表动态生成（偏移/名称/访问对齐 DUT，避免硬编码错位）
- STATUS 类 W1C 语义、prdata 组合返回（读写一致）
- 跨 agent 动态寄存器（UART 并发更新 STATUS/RXDATA）→ scoreboard ignore_prdata

### 4.5 激励充分性与收敛
- 每轮递增 seed（+UVM_SEED）保证随机序列不同
- UART 串行验证走独立 loopback（波特率对齐 DUT）；full regression 专注 APB DUT 覆盖率
- 覆盖率饱和（21%）时 L3 正确路由：GENERATE_DIRECTED_TEST → EXPAND_SEEDS → 签核拒绝

## 5. 运行入口

```bash

# 收敛验证（3 轮）
PYTHONPATH=src python scripts/run_converge_check.py

# 单模块验证
PYTHONPATH=src python scripts/verify_passive.py      # passive agent 生成 + 编译
PYTHONPATH=src python scripts/verify_regression.py   # 全回归 + 覆盖率

```

## 6. 现状与已知边界

- ✅ 编译 PASS / 仿真 PASS / 真实覆盖率（21.01%）/ 7-agent 全接入 / 签核证据链
- ⚠️ 覆盖率饱和 21%：随机 APB 激励只覆盖寄存器读写路径；UART TX/RX/FIFO 状态机
  需定向激励（写 TXDATA + 串行输入）——L3 的 GENERATE_DIRECTED_TEST 动作执行
  待增强为真正注入定向激励（当前只生成约束文件，未接入回归）
- ⚠️ UART 与 APB 并发时 UART driver 卡死（@(vif.cb) 竞争，根因待查）——已规避
  （UART 验证走独立 loopback，full regression 不启动 UART seq）

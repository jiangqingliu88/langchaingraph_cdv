这套内容**不是业界某个现成的标准方法学名称**，而是作者自定义的一套**验证覆盖率与追溯治理框架**。从标题看叫“**视图方法学落地：统一 ID 体系与追溯骨架**”，更准确地说，它是一套：

> **基于统一 ID 体系和 Cell 枢纽的“验证追溯 + 覆盖率视图 + 证据闭环”方法学**

可以简称为：

> **Cell 枢纽型验证视图方法学**  
> 或 **统一 ID + 证据矩阵的验证追溯方法学**

## 它融合了哪些成熟方法学/实践

| 来源 | 在文中的体现 |
|---|---|
| **需求追溯矩阵 RTM** | FEAT → CG/CP → P → CELL → SVA/SB → EVD → GAP/WVR |
| **覆盖率驱动验证 CDV** | Covergroup、Coverpoint、Bin、Cross、覆盖率目标、缺口 GAP |
| **UVM 验证方法学** | SVA、Scoreboard、Sequence、Constraint、Test、Seed |
| **V 模型/验证闭环** | 需求、功能、通路、场景、判定、激励、证据、管理分层 |
| **基于模型的系统工程 MBSE/追溯图** | 以 Cell 为枢纽的有向追溯图 |
| **单一事实来源 SSOT** | 每个实体一个 YAML，禁止多处维护 |
| **CI 门禁与质量治理** | schema 校验、孤立检测、vacuous 检测、未执行检测、Cell 完整性 |
| **看板/矩阵视图** | 覆盖矩阵、SVA 矩阵、SCB 矩阵、通路视图、场景视图、证据视图 |

## 它的核心特征

1. **七层 ID 体系**：FEAT/CG/CP/BIN/X → P/STG/BR → SCN/CMB → SVA/SB → SEQ/CST/TST/SEED → CELL/EVD → GAP/WVR/BATCH/MON/COL/CFG/VER。
2. **CELL 是唯一枢纽**：功能组 × 通路形成矩阵格子，所有上下游实体都挂到 Cell。
3. **YAML 是 SSOT**：每个实体一个登记文件。
4. **Cell 自动生成**：不允许手工维护。
5. **视图自动生成**：矩阵、通路、场景、证据、缺口看板都从 YAML 生成。
6. **CI 强制门禁**：孤立、vacuous、未执行、Cell 无 checker、非法 bin、未审批豁免都 fail。

## 它不是什么

- 不是 ISO 26262、DO-254 这类功能安全标准；
- 不是单纯的 UVM 方法学；
- 不是单纯的覆盖率方法学；
- 也不是某个 EDA 工具自带的标准流程；
- 目前看是**团队/作者自建的一套验证治理规范**。

## 一句话定位

**这是一套“以 Cell 为枢纽、以统一 ID 为骨架、以 YAML 为单一事实来源、以自动生成视图和 CI 门禁为落地手段”的验证追溯与覆盖率证据闭环方法学。**  
它本质上是 **RTM + CDV + UVM 验证资产 + SSOT + CI 治理** 的组合创新，而不是一个现成标准方法学。
